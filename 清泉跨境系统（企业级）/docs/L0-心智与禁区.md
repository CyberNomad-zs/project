# L0 — 心智与禁区

> 上岗前速读。不代替 Skill；违反下列条款视为流程失败。

## 1. 心智模型

| 错误想法 | 正确想法 |
|----------|----------|
| AI 很强，直接说「帮我做完」 | AI 缺完整上下文与责任；**人**守门禁 |
| Spec 浪费时间 | 模糊需求下，**无 Spec = 返工工厂** |
| 门禁太多 | Spec + **MVP** + Plan/Findings/Diff；热修可跳前几道，不可跳 Diff |
| Spec 批了就该全做 | Spec 是全景；**MVP** 才是本迭代交付面 |
| 有 Plan 就够了 | 员工场景还要 **架构交付物**（内部结构） |
| 先写码再补文档 | Intent → Spec → MVP → Arch → Plan → 码 → Diff |
| 聊天里说了批准 | **进仓制品**才算节点完成 |
| Vibe 等于生产 | **Vibe ≠ 生产**；生产要 harness 与人 |

> 模型负责「写」，**Harness（清单/门禁/脚本）负责「不翻车」**。

---

## 2. 角色分工

| 角色 | 负责 | 不负责 |
|------|------|--------|
| 执行者（人） | 答澄清、批门禁、看 Diff、升级审批 | 擅自 G3、跳过 Spec |
| Agent | 按 SOP 跑、列清单、写草稿与代码 | 产品拍板、生产发布 |
| 授权审批人 | G3、架构、合规例外 | 不必替你点每个 Gate A（默认可执行者批） |

---

## 3. 禁区（Never）

### 流程

- 无用户批准 Spec 写业务功能
- Spec 已批但未批 MVP/架构（非热修）就 Plan/写码
- 门禁只口头批、无进仓交付物
- 未出现哨兵句就继续写码 / push
- 「先做了再说」、私自扩 scope / 扩出 Ship-now 或 ARCH 边界

### 安全与合规（G3）

- 生产部署、删数、不可逆迁移
- 密钥 / Token 进仓库
- 资金结算逻辑无人审
- 外部系统生产凭据、法定/合规字段无人审
- 真实生产 PII 进 Prompt/日志当调试数据

### 表述（写进 Spec/AC 时）

禁止：`可能` `大概` `适当` `优化一下` `尽快` `更好用` `更智能` 等不可测措辞。

---

## 4. 例外怎么走

1. 写明：破什么规则、为什么、影响、有效期  
2. 批准人：授权审批人姓名  
3. 记录：写进 PR 与 Spec RISKS  
4. **无批准人 → 不破例**

> 输入可验证 → 动作有责任人 → 输出可被下一环使用 → 通过 / 阻断 / 例外。
