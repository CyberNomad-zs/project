# 运维与排障

## 日常操作

| 场景 | 操作 |
|------|------|
| 每日手动 | 打开店铺 → 广告列表 → 扩展 Popup → 立即抓取（业务日按英国时区） |
| 定时 | **中国 17:20** 计划任务（`install-daily-task.ps1`）；扩展默认定时也是 17:20。**不要**设到中国早上 7–9 点 |
| 查结果 | 飞书多维表按「日期 / 店铺」筛选；同一天多套花费 → 多半是早抓/重复 APPEND |
| 导出日志 | Popup「导出」得到 JSON |
| 新机器部署 | 双击 `安装环境.bat` → 安装/登录紫鸟客户端 → 配置 `stores.config.json` |

## 环境依赖一键安装

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install-deps.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\install-deps.ps1 -ApiKey "紫鸟开放平台APIKey"
powershell -ExecutionPolicy Bypass -File .\scripts\install-deps.ps1 -UseOfficialMirror
powershell -ExecutionPolicy Bypass -File .\scripts\install-deps.ps1 -DoctorOnly
```

| 会装 | 不会装 |
|------|--------|
| Node.js LTS（**默认 npmmirror 下载 MSI**，失败再 winget） | 紫鸟桌面浏览器（需官网/安装包） |
| `@ziniao-open/cli`（npm **默认 registry.npmmirror.com**） | Python（仅图形启动器需要，可选） |

`doctor` 失败常见原因：紫鸟客户端未开、未登录、API Key 未配置、本机 Bridge 端口不可用。

脚本装不上时：完整手动步骤见 **[手动安装环境.md](手动安装环境.md)**。

## 日志落盘（排查必看）

| 来源 | 路径 | 何时产生 |
|------|------|----------|
| 美化启动器每次按钮任务 | `logs/gui-时间-任务名.log` | **一点按钮就写**，失败也会有 |
| 多店脚本运行全文 | `logs/multi-store-run-时间.log` | 预览/干跑/正式一开始就写 |
| 预览列表结果 | `logs/multi-store-list-时间.json` | 「预览店铺列表」成功 |
| 多店抓取汇总 | `logs/multi-store-时间.json` | 干跑/正式跑完 |
| 多店早期失败 | `logs/multi-store-fail-时间.json` | Bridge 连不上、配置错误等 **throw 前** |
| 每日 17:20 /「立即跑日报」 | `logs/daily-report-时间.log` | 包装脚本始终写 |
| 单店抓取调试 | `logs/scrape-debug-*.json` | 单店失败或调试保存 |

以前：预览失败（如紫鸟未开）只在 GUI 窗口显示，**不会**写 `multi-store-*.json`，同事会觉得「logs 没自动记录」。  
现在：GUI + 脚本两侧都会在 `logs/` 留下文件，把最新 `gui-*.log` 或 `multi-store-fail-*.json` 发给运维即可。

## 常见问题

### 0. 预览店铺列表失败：无法连接 Bridge / 127.0.0.1:9481

典型输出（节选）：

```text
store list failed: { "ok": false, "error": { "type": "network",
  "message": "无法连接... Bridge (http://127.0.0.1:9481)" } }
--- 结束 exit=1 ---
```

| 原因 | 处理 |
|------|------|
| 紫鸟桌面客户端未打开 | 打开客户端并保持在线 |
| 未登录 | 登录成员账号 |
| 客户端刚启动未就绪 | 等 10～30 秒再点预览 |
| 只装了 Node/ziniao-cli | **不够**，必须有桌面客户端提供 Bridge |
| 防火墙拦本机 9481 | 放行紫鸟 / 本机回环 |

自检：启动器点「环境自检」，或命令行 `ziniao-cli doctor`。

### 1. 未找到 TikTok 页面

- 必须在 **紫鸟店铺窗口** 内打开 `*.tiktok.com` / `ads.tiktok.com` 广告相关页。
- 扩展图标在客户端主界面可能无目标 tab；请在店铺浏览器窗口点扩展。

### 2. 未识别到广告数据表格

- 确认已进入 **广告系列列表 / Shop Ads / GMV Max 报表**，而非首页。
- 等表格加载完成后再点抓取。
- 若 TK 改版表头变化：更新 `content/content.js` 中 `HEADER_ALIASES`，或依赖 API hook（需先在页面操作触发报表请求）。
- 张威开通测试店后，建议用 DevTools Network 固化接口字段映射。

### 2.1 飞书数字明显偏大 / 不是「昨天」单日

| 现象 | 原因 | 处理 |
|------|------|------|
| 销量/销售额像一周汇总 | 广告数据面板默认日期是 **近 7 天**，旧脚本只贴标签「昨天」未改页面 | 升级后脚本会自动点「昨天」；看 run log 是否有 `date range confirmed` |
| log 有 `WARN date pick failed` | 页面改版或未进广告面板 | 手动打开广告数据面板，确认右上角有日期区间与「昨天」快捷项 |
| log 有 `date after pick still A~B` | 点击后区间未变 | 把 `waitAfterDateChangeMs` 调大到 12000；或手动点「昨天」后看 DOM 是否变化 |

相关脚本：`scripts/set-date-range.js`（open → pick → status），由 `run-multi-store.ps1` 在抓表前调用。

### 2.2 早上花费偏小 / 同一天两套花费（时区）

| 现象 | 原因 | 处理 |
|------|------|------|
| 07:30 左右抓取花费明显偏小 | 中国早上 ≈ 英国日刚开始；抓「今天」或日切未稳 | **不要早抓**；用 `dateMode=yesterday` + 中国 **17:20** |
| 同日 07:30 与 09:58 两套数 | 飞书是 APPEND；早抓半截 + 晚些重跑完整 | 删掉早抓那批；保留完整版 |
| 业务日与后台对不上 | 旧逻辑按**中国本地**算昨天/今天 | 现已按 `Europe/London`；日志应有 `bizTz=GMT Standard Time`、`UK-now=...` |
| 手动设 `dateMode=today` 仍变昨天 | 英国时 < `minUkHourForToday`（默认 20）时脚本强制 yesterday | 正常保护；等英国傍晚后再抓 today，或继续用 yesterday |

对照：中国 08:00 ≈ 英国 00:00（冬令差 8 小时，夏令差 7 小时）。

### 3. 飞书连接失败

- 检查 App ID / Secret、应用是否已发布、是否添加到该多维表格。
- 检查 app_token、table_id 是否与 URL 一致。
- 字段名是否与《飞书表格建表说明》一致。

### 4. 写入成功但飞书看不到

- 刷新多维表；确认看的是正确 table。
- 是否仍处于「干跑」模式（干跑不写表）。
- 日期字段为时间戳，视图中确认日期列格式正确。

### 5. 定时未执行

- `chrome://extensions` 查看插件是否启用。
- 系统休眠/退出紫鸟会导致 alarm 无法可靠触发。
- 查看 Popup 最近日志是否有「定时任务触发」。

### 6. 部分字段为空（status=partial）

- 页面列与别名未完全匹配；以 partial 写入便于后续补数。
- 导出预览 JSON 对照页面列名，补充同义词。

## 安全

- 不要将 App Secret 提交到 Git。
- 店铺密码由紫鸟托管，插件 **不采集、不存储** 登录密码。
- 离职交接：在飞书撤销应用权限，在紫鸟取消账号分配。

## 版本升级

1. 修改 `extension/manifest.json` 的 `version`。
2. 运行 `scripts/package-zip.ps1`。
3. 开放平台上传新版本；调试期可直接「重新加载」已解压扩展。
