# L3 — 评审与发布

> Diff 门 + PR + 发布禁区。对应 Gate C 与 G2/G3。  
> **不做全自动合 main / 发生产。**

## 1. Gate C — Diff（不可跳）

即使是单文件热修，**也必须**过 Diff 门。

检查：

| 项 | 问自己 |
|----|--------|
| 范围 | 是否改了不该改的文件？ |
| 删除 | 是否误删逻辑？ |
| 密钥 | 是否有 Token、密码？ |
| 测试 | 有结果或可复现步骤吗？ |
| AC | MVP Demo / P0 是否覆盖？ |
| MVP | Success check 是否达成？ |
| G3 | 是否碰资金/凭据/合规字段/生产数据？ |

Agent：`skill-pack/06-review-ship/` + `checklists/gate-c-diff.md`

---

## 2. PR 最低要求

- [ ] 链接 SPEC / MVP / ARCH / PLAN / ACCEPTANCE  
- [ ] 做了什么 / 没做什么  
- [ ] 如何测试  
- [ ] 风险与回滚  
- [ ] 门禁跳过说明（若有）  
- [ ] Gate C 已获批  

建议：第二 Agent 或人工做一次 review（生成 ≠ 校验）。

---

## 3. 发布策略

| 环境 | 操作者 | 说明 |
|------|--------|------|
| 本地 / 开发 | 执行者+Agent（G1） | Gate C 后 |
| 共享测试 | 确认后 G2 | 预览影响 |
| 生产 | **仅授权人**（G3） | 禁止无授权自主 |

发布前可加问：

- [ ] 范围是否仅在批准的试点/批次内？  
- [ ] 凭据是否走密钥管理？  
- [ ] AI 对客是否需披露？  
- [ ] 审计日志字段是否足够且无多余敏感数据？  

完整表：[spec-compliance-checklist.md](../templates/spec-compliance-checklist.md)

---

## 4. DoD

- [ ] Gate C 批准  
- [ ] 测试或手工验收可复现  
- [ ] 无密钥与生产数据进仓  
- [ ] ACCEPTANCE P0 已勾或说明未做  
- [ ] 回滚路径可知  

---

## 5. 合并哲学

- merge 前：Gate C + 人审  
- 不做：Agent 自动合 main、自动生产发布  
- 例外：批准人 + 理由 + 有效期（见 L0）

---
