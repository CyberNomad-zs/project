# 日报总结分析

多店抓取结束后（`run-multi-store.ps1` / 每日 17:20 任务）会自动生成总结分析。

## 产出内容

| 产出 | 路径 / 位置 |
|------|-------------|
| 完整 Markdown 报告 | `日报/日报-{业务日期}.md` |
| 一句话简报 | `日报/简报-{业务日期}.txt` |
| 结构化 JSON | `日报/日报-{业务日期}.json` |
| 快捷打开 | `日报/最新日报.md` · `日报/最新简报.txt`（每次生成覆盖） |
| 控制台 | 打印简报 + 分店汇总表 |
| 飞书（可选） | 写入汇总行（见下） |
| 抓取调试日志 | 仍在 `logs/`（与日报分开） |

### 分析包含

1. **总览**：成功店数、系列数、花费/销量/销售额合计、综合 ROI  
2. **分店汇总**：每店系列数与 KPI、贡献 TOP 系列  
3. **亮点**：销售额最高店、ROI 最高店、单系列 TOP  
4. **风险**：综合 ROI 低于阈值、花费>0 销售额为 0、抓取失败店  
5. **系列 TOP**：按销售额 / 按 ROI  

## 飞书汇总行

当 `analysis.writeSummaryToFeishu: true` 时，在明细之后追加：

| 品名 | 店铺 | 含义 |
|------|------|------|
| 【店铺汇总】 | 各店名 | 该店花费/销量/销售额/综合 ROI |
| 【全店汇总】 | 全店 | 所有店合计 |
| 【日报分析】… | 全店 | 品名字段附带简报摘要（截断） |

筛选明细时可排除品名以 `【全店汇总】` / `【店铺汇总】` / `【日报分析】` 开头的汇总行（勿用裸词「分析」，以免误伤系列名中的「数据分析」）。

## 只写汇总（不重抓）

明细已在飞书、仅汇总错误/为空时：

```powershell
# 预览
powershell -ExecutionPolicy Bypass -File .\scripts\rewrite-summary-from-feishu.ps1 -BizDate 2026-08-11 -DryRun true

# 正式：删该日旧汇总行后重写【店铺汇总】/【全店汇总】/【日报分析】
powershell -ExecutionPolicy Bypass -File .\scripts\rewrite-summary-from-feishu.ps1 -BizDate 2026-08-11
```

- 从飞书读该日**明细**（自动排除系统汇总行；同店+同品名去重）
- **不**重抓广告页、**不**重写系列明细
- 同步刷新本地 `日报/日报-{日期}.*`

## 配置

`config/stores.config.json`：

```json
"analysis": {
  "enabled": true,
  "lowRoiThreshold": 3,
  "writeSummaryToFeishu": true
}
```

| 项 | 说明 |
|----|------|
| `enabled` | 是否生成分析 |
| `lowRoiThreshold` | ROI 低于该值记为风险（默认 3） |
| `writeSummaryToFeishu` | 是否把汇总行写入飞书 |

## 说明

- **金额单位：美金 (USD)**。广告花费、销售额与 TikTok 广告后台一致按美金计算；若页面为英镑等，脚本会按 `config.currency.ratesToUsd` 换算后再写入飞书/日报。  
- 综合 ROI = 销售额合计 ÷ 花费合计（花费为 0 时特殊处理）  
- 页面 ROI 与综合 ROI 可能因归因窗口不同而不完全一致  
- 分析失败不会中断主流程（记 non-fatal 日志）
