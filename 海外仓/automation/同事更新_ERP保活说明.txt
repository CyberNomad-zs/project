ERP 循环保活 + 关窗自动续跑 更新包（2026-07-30）
====================================================

本包包含两块修复（一次覆盖即可）：
  A. ERP 循环掉线 / 保活（等会话时不再轻易退出）
  B. 浏览器被点「×」关掉后，循环自动重启窗口并续跑

--------------------------------
A. 现象（旧：掉线）
--------------------------------
全流程循环跑一两轮后日志出现：
  会话失效（保活期间检测到）。退出，请重新登录后再启动。
需要反复手动登录再开 [A]。

原因（旧代码）
1. 等待期只 ping isLogin 接口，往往不能续期 cookie
2. 网络超时被当成掉线，整进程退出
3. 掉线后直接退出，同事还要重登+重启脚本

--------------------------------
B. 现象（旧：关浏览器就挂）
--------------------------------
发完货 / 循环空闲时，若把自动化浏览器窗口点「×」关掉，
下一轮或保活时直接报 Target closed / Browser has been closed，循环失败退出。
以前只能一直开着浏览器窗口。

本包新行为：检测到关窗后自动重新打开浏览器，用本机 profile 会话续跑；
若会话仍有效则无需重登；失效则同窗口打开登录页等你过滑块。

--------------------------------
本包改动文件（解压覆盖 automation 根目录）
--------------------------------
- core.py
- full_loop.py
- status_update_loop.py
- shipping_loop.py

--------------------------------
同事机更新步骤
--------------------------------
1. 停掉正在跑的 full_loop / 发货循环 / 启动器控制台
   （在对应黑窗口 Ctrl+C，或直接关控制台；不要只关浏览器）
2. 备份旧文件（可选）：把上面 4 个文件复制到 backup 文件夹
3. 解压本 zip，把 4 个 .py 覆盖到同事本机 automation 目录
   （常见路径类似 D:\automation_20260720\automation 或你们实际目录）
4. 不要动这些（各机自己的）：
   - secrets.py（含密码）
   - .browser_profile（本机登录态）
   - logs/
5. 重新登录 ERP（建议更新后做一次）：
     python capture/erp_manual_login.py
   或启动器 [1] / 美化启动器「登录 ERP」
6. 再开全流程循环 [A]（或发货循环 [6] / 跟踪号循环 [5]）

如何确认已更新成功
------------------
打开 core.py，搜索下面任一关键词，能搜到即本包版本：
  is_browser_dead_error
  ensure_browsers
  recover_after_browser_dead
  KEEPALIVE_SEC

新行为摘要
----------
- 等待期每约 2 分钟真实打开订单页做保活（更不容易空闲掉线）
- 网络抖动不再误杀循环
- 真掉线时：同窗口打开登录页 + 飞书提醒，在自动化浏览器里完成滑块即可继续
- 浏览器被点 × 关掉：自动重启 ERP(/WMS) 窗口并续跑，不必一直盯着不关窗
  （某一轮做到一半被叉掉，当轮未完成的会等下一轮整轮再跑，一般无妨）

重要：双机不要同时真跑
----------------------
- 你和同事的电脑不要同时对同一赛狐账号跑 [A]/[6] 真发货
- 会抢同一批「待处理」订单，可能重复下单/漏发/互相踢会话
- 约定：同一时间只允许一台机开真跑常驻；另一台只看日志/空跑，或只跑 sellfox-bridge 对账

不要覆盖
--------
- secrets.py（含密码）
- .browser_profile（本机登录态，各机各自登录）
- logs/（各机本地日志）
