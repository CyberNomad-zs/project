# 仪表盘方案：集团总览 + 店铺仪表盘

> 数据底座：飞书多维表格 **母表（全量）+ 子表（按店）**  
> Base：`FEISHU_BITABLE_APP_TOKEN`（当前 `TkW0bXEAAa3Fo3sdKagcL9fTn2b`）  
> 子表注册：`data/feishu_shop_tables.json`  
> 逻辑店（6）：Ledvia-UK / Nottac-UK / 特米-UK / 昇新-UK / 起的快-UK / 字同道合  

本方案分两套，**不要做成一套带筛选的大屏**：

| 套件 | 受众 | 数据源 | 目标 |
|---|---|---|---|
| **A. 集团总览** | 老板、唐丹、主管 | **母表** | 跨店健康度、谁红、要不要升级 |
| **B. 店铺仪表盘** ×6 | 该店运营负责人 | **该店子表** | 今日必办、本店广告/库存/闭环 |

## 0. 设计原则（两套通用）

1. **一屏决策**：先红灯与清单，后趋势图。  
2. **禁止双 Y 轴**：销售额与 ACOS 分两个图，不要叠在一根轴上。  
3. **状态色专用**：红/橙/黄/绿只表示任务等级与健康状态，不当「系列色」。  
4. **系列色固定顺序**（店对比时）：特米 → Ledvia → Nottac → 昇新 → 字同道合 → 起的快，不要随排序换色。  
5. **日期筛选默认近 7 天**；明细表默认「最新业务日」。  
6. **母表日期字段注意**：ASIN 母表「日期」可能是**文本**；子表多为**日期类型**。飞书图表筛选时以实际字段类型为准；若筛选异常，先用「每日汇总」表的日期。

### 状态色建议

| 语义 | 用途 | 飞书侧 |
|---|---|---|
| 红 | red 任务、严重断货 | 条件格式 / 数字卡片告警 |
| 橙 | orange 任务、ACOS 超红线 | 同上 |
| 黄 | 观察 / 待核实 | 同上 |
| 绿 | 已关闭 / 指标正常 | 同上 |
| 灰 | 清仓 / 暂停补货 | 结构图 |

## A. 集团总览仪表盘

### A1. 名称与入口

- 仪表盘名：`集团总览-ASIN健康度`  
- 挂在 base 根目录，权限：老板 / 唐丹 / 主管
