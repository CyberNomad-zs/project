## 一、项目目标与范围

**输入**：产品**白底图**（一张或多张）。
**输出**：全自动完成并上传到 1688 自有店铺：
- 主图（多张：场景图/卖点图/尺寸图等）
- 主视频
- 详情页
- 商品发布（含标题、类目、属性、SKU、价格、库存）

**范围边界**：
- ✅ 本系统负责：内容生成 + 素材入库 + 类目/属性组装 + 发布上架
- ❌ 不负责：选品、定价策略、供应链（这些由运营人工决定，作为输入参数传入）

**目标店铺**：常州易之来照明有限公司的 1688 店铺（诚信通，主营照明/灯具）。

## 四、关键结论（已验证，务必先读）

### 4.1 1688 发布 = 解决方案制 + Schema + 前端 JS SDK（不是老 API）
- 新版控制台**没有**独立"创建应用"，是**订购解决方案**时一并建应用。
- 我们用的方案：**「新版商品管理解决方案（商家自用版）」**，`solutionKey=1671675923686`，已订购。
- 发布用**全新 Schema 规则体系**：不是老的 `alibaba.product.add`（老 API 正在下线）。
- ⚠️ **发布强制配合前端 JS SDK**（含风控算法 `pcAlgorithmSdk`）。纯后端直接调 API 大概率被风控挡 → **发布层必须用浏览器（Playwright）承载 JS SDK**。这是本项目最大的技术特点，见 §6-M4。

### 4.2 凭证已就绪，且 accessToken 永久有效
- 应用「易之来商品自动发布」已建好，appKey=`9901201`。
- 是**企业自用·多用户授权**，主账号已授权，**accessToken 永久有效，无需 OAuth 回调流程**。
- 全部凭证存于 **`config/1688_credentials.json`**（含 appSecret、accessToken）。
- 因此 OAuth 回调那套流程本项目**完全用不上**（直接读 `config/1688_credentials.json` 里的永久 token 即可）。
- 应用当前状态"开发测试中"，流量 **5000 次/天**。

### 4.3 内容生成 = zapi 的 grok 模型
- 网关 zapi（`https://zapi.aicc0.com`，OpenAI 兼容），key 在 `config/`（见 §5）。
- 参考实现：oracle 项目的 studio，源码 `~/Desktop/zapi/grok-studio/client.py`，线上 https://studio.aicc0.com。
- ⚠️ oracle 的 `信息.md` 含高敏基础设施信息，**只读不外传**。
- 模型**统一用 grok 最新款**（用户明确要求）：见 §7-附录A。

## 六、模块设计

### M1 内容生成层 `src/generate/`
职责：白底图 → 主图 / 主视频 / 详情页。全部走 zapi grok（API 契约见 §7-附录A）。

- **主图生成** `image.py`
  - 输入：白底图（本地路径）+ 卖点文案 + 画幅（默认 `1:1` 方图）
  - 方式：`POST /v1/images/edits`（图生图，把白底图当输入 + prompt 生成场景/卖点图）
  - 模型：`grok-imagine-image-quality`（高保真 2k）
  - 输出：N 张主图落地到 `output/<商品id>/main_*.png`
- **主视频生成** `video.py`
  - 输入：一张主图（作首帧）+ 运动 prompt + 时长（默认 5s）
  - 方式：`POST /v1/videos`（i2v，Sora 异步协议：提交→轮询→取 mp4）
  - 模型：`grok-imagine-video-1.5-preview`（图生视频，需首帧）；备选 `grok-imagine-video`
  - 输出：`output/<商品id>/main_video.mp4`
- **详情页生成** `detail.py`
  - 方式：可先用"多张卖点图 + 模板拼接成长图"（Pillow 拼接），也可用 grok 生成分段图后拼接
  - 输出：`output/<商品id>/detail_*.png`（或拼好的长图）
- 统一封装 `zapi_client.py`：base_url + key 读 config；实现 `gen_image()`, `edit_image()`, `gen_video()`（含轮询）。

### M2 素材入库层 `src/media/`
职责：把 M1 生成的本地图/视频传到 1688，拿到发布可用的图片银行 URL / fileId / 视频 ID。
- **硬约束**：主图/详情图**必须先传图片银行**才能用于发布，外链图直接发会失败。
- 图片：走 1688 图片银行上传接口（订购方案后在"API及消息列表/能力列表"里确认确切接口名，历史名为 `alibaba.photobank.photo.add`，新版以方案内接口为准）。
- 视频：走 1688 视频上传通道（**不走图片银行**），发布时关联视频 ID。确切接口名待方案内文档确认。
- 输出：`{main_images:[{url,fileId}], detail_images:[...], video_id}`。

### M3 类目 / Schema 层 `src/category/`
职责：确定商品类目、拉取该类目的发布规则（Schema），组装成商品 json。
- 类目匹配：关键词 → categoryId（历史接口 `alibaba.category.searchByKeyword`，新版以方案内为准）。
- **Schema 流程**（新版核心）：
  1. 调接口拿该类目的 Schema（返回 json 字符串，描述每个 field 的 type / 规则 / 是否必填）。
  2. 解析 Schema，做**动态映射**：把本地商品数据（标题/属性/SKU/价格/库存/图片）映射到 Schema 的 field 上。
  3. 关注 field 的 **type** 和规则做前置校验。
  4. 生成最终商品 json。
- ⚠️ 官方强调：不要写死参数，要做变更检测 + 动态映射（业务规则变化快）。

### M4 发布层 `src/publish/`（**本项目技术难点**）
职责：用组装好的商品 json 完成发布/更新，**必须在浏览器里承载 1688 前端 JS SDK**。
- 方案：**Playwright 驱动 Chromium**，注入 1688 登录 cookie（`config/1688_cookies.json`），加载页面并注入：
  ```html
  <script>window.__1688_OPEN_SDK_CONFIG = { appKey: '9901201', appName: '易之来商品自动发布' };</script>
  <script src="https://o.alicdn.com/fuwu-assets/alife-open-sdk/index.js"></script>
  ```
  然后 `window.__1688_OPEN_SDK.load({sdkNameList:['pcAlgorithmSdk', ...]})` 加载风控算法 SDK，
  用它生成发布 API 所需的风控参数/签名，再发起商品发布调用。
- 关键待验证：
  1. 发布调用是"在浏览器里由 SDK 直接发"，还是"SDK 生成 token 后由后端带 token 调 API"。两种都要在联调阶段实测确认（见 §10）。
  2. "开发测试中"状态能否直接发到线上店铺，还是要先走"提交上线"。
- 产出：发布成功返回的商品 ID，写入结果报告。

### M5 编排 / CLI `src/pipeline.py` + `cli.py`
职责：串起 M1→M2→M3→M4，支持批量。
- 输入：`input/` 下每个商品一个子目录（白底图 + 一个 `meta.json`：标题/类目关键词/卖点/价格/SKU/库存/运费模板等）。
- 流程：读商品 → 生成内容(M1) → 入库(M2) → 组装(M3) → 发布(M4) → 记录结果。
- 输出：`output/<商品id>/` 存所有素材 + `report.json`（成功/失败/商品ID/错误）。
- 要点：每步可断点重试；失败不影响其它商品；日志清晰。

## 七、API 契约附录

### 附录 A：zapi 生图 / 生视频（OpenAI 兼容）

**通用**：`Authorization: Bearer <zapi_key>`，base `https://zapi.aicc0.com`。

**A1. 文生图** `POST /v1/images/generations`
```json
{ "model": "grok-imagine-image-quality", "prompt": "……", "user": "{\"aspect_ratio\":\"1:1\"}" }
```
返回 `{"data":[{"b64_json":"…"}]}` 或 `{"data":[{"url":"…"}]}`。

**A2. 图生图 / 改图（白底图→主图，本项目主用）** `POST /v1/images/edits`
- `multipart/form-data`：字段 `model`、`prompt`，每张输入图字段名都叫 `image`（可多张）。
- 用途：白底图作为输入，prompt 描述要生成的场景/卖点样式。

**A3. 生视频（Sora 异步协议）**
1. 提交 `POST /v1/videos`
   ```json
   {
     "model": "grok-imagine-video-1.5-preview",
     "prompt": "……",
     "seconds": "5",
     "image": {"url": "https://…/首帧.jpg"}
   }
   ```
   - i2v 首帧用 `image`；首尾帧加 `last_frame_image`；多参考图 `reference_images:[...]`（grok 视频 ≤7）；续写 `reference_video`。
   - ⚠️ 图片字段传 `{"url":...}` 对象最稳（传字符串可能被拒）。
   - 返回 `{"id":"<video_id>"}`。
2. 轮询 `GET /v1/videos/{id}` → 查状态/进度。
3. 完成后 `GET /v1/videos/{id}/content` → 返回 mp4 二进制。

**A4. grok 最新模型清单**
| 类型 | 模型 | 说明 |
|---|---|---|
| 主图 | `grok-imagine-image-quality` | 高保真，默认 2k（首选）|
| 主图(平价) | `grok-imagine-image` | 平价文生图 |
| 主视频 | `grok-imagine-video-1.5-preview` | 图生视频 i2v，需 1 张首帧，1–15s（默认5）|
| 主视频(备选) | `grok-imagine-video` | t2v/i2v，原生音频，多参考图≤7，1–15s |
| 画幅 aspect_ratio | `1:1 / 3:4 / 4:3 / 9:16 / 16:9 / 2:3 / 3:2` | 经 `user` 字段传 |

> 电商建议：主图用 `1:1`；详情/竖版视频可用 `3:4` 或 `9:16`。prompt ≤ 2000 字符。

### 附录 B：1688 商品发布（Schema 模型）
- 方案文档入口（登录后看）：`https://open.1688.com/solution/solutionDetail.htm?solutionKey=1671675923686`

## 十、风险与待验证项（务必优先解决）

1. **【最高】JS SDK 发布模式**：发布到底是"浏览器里 SDK 直接发"还是"SDK 出 token、后端带 token 调 API"？→ P2 阶段用 API 测试工具 + 抓包实测确认。决定 M4 架构。
2. **开发态能否直发线上店铺**：应用现"开发测试中"。确认 5000次/天 额度是否可直接发到线上店铺，还是必须"提交上线"审核。→ 发一个测试商品验证。
3. **cookie 过期**：`config/1688_cookies.json` 会过期，Playwright 承载 JS SDK 依赖登录态。需要**半自动 cookie 刷新**方案（人工扫码/复用 auth_tool 思路），并检测失效。
4. **grok 生图电商适配度**：grok 生的主图/详情页是否达电商上架审美与合规（尺寸、留白、文字清晰）。→ P0 阶段人工评审样张，不行再调 prompt/模板或换模型。
5. **类目属性必填项**：不同类目必填属性差异大，动态映射要覆盖。→ 先锁定主营照明/灯具几个高频类目跑通。
6. **合规**：仅自研自用、自有店铺，勿做成对外三方工具（违反资质承诺）。图片/视频生成内容需合规。

## 十一、测试与验收标准

- **单元**：M1 各生成函数、M3 Schema 映射有单测（可用假数据/录制响应）。
- **联调**：先发 1 个**测试商品**端到端跑通（白底图→上架→拿到商品ID→前台可见）。
- **验收**：给定 N 个商品的 `input/`，`python cli.py` 后：
  - 每个商品有完整 output 素材；
  - 成功发布的返回商品 ID；失败的有明确错误原因；
  - `report.json` 汇总成功率。
