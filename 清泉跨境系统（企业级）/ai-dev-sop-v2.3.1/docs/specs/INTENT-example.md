## §0 极速卡

| # | 字段 | 填写 |
|---|------|------|
| 0.1 | 一句话目标 | 让客服在工单详情页 1 次点击生成「用户可读的进度摘要」 |
| 0.2 | 谁会用 | 一线客服 |
| 0.3 | 典型场景 | 用户追问「我的单到哪了」时，客服打开工单详情 |
| 0.4 | 痛点 | 现在要翻 5～8 条系统日志拼话术，平均 4 分钟且易说错状态 |
| 0.5 | 怎样算做成 | 在测试环境：从打开详情到复制出摘要 ≤30 秒；摘要含状态+最近事件时间；错误状态时显示明确失败原因 |
| 0.6 | 明确不做 | 1. 不做自动回复用户 2. 不做多语言 3. 不改工单状态机本身 |
| 0.7 | 开工类型 | 改已有系统（feature） |
| 0.8 | 时间盒 | 本迭代内可演示；无生产全量硬截止 |
| 0.9 | 硬约束 | 只能读现有工单 API；不能直连生产库；摘要默认不进长期日志 |
