## 2. 指标语义：谁说了算（SoT）

### 2.1 店级「全店 GMV / 订单」→ ① 店铺分析

| 指标 | SoT | 说明 |
|------|-----|------|
| 店日 GMV / 订单 / 客户 | `fact_tiktok_shop_daily` | 商家中心 **① 店铺数据分析** / shop-modules |
| 广告花费 / 系列 ROI | `fact_ads_campaign_daily` 汇总 | **横切**；可并列展示，**不是**店日 GMV 的替代定义 |
| 健康分 | `fact_tiktok_health_daily` | 横切提醒，不进 GMV 加总 |

**禁止：** 用广告 `revenue`/`spend` 覆盖或「修正」① 店日 GMV。  
**允许：** 总览缺店日时展示「广告估」并**明确标源**（`data_source=ads_rollup`），不可静默当真相。

### 2.2 视频归因 → ② 视频内容

| 指标 | SoT | 说明 |
|------|-----|------|
| 视频归因 GMV / 订单 / 曝光 / 播放 | `fact_tiktok_content_daily` | 内容分析 · 视频详情；**近 7 天窗**，不拆日 |
| 商品卡 CTR/CVR | `fact_tiktok_product_traffic_daily` | 同属 ② 生态 |

**禁止：** 把单条视频归因 GMV 加总后当作 ① 全店 GMV（归因重叠、窗口不同）。  
**允许：** 同店同窗做**对照图**（内容贡献 vs 店日），差值只解读不回填。

### 2.3 达人归因 → ③ 达人表现

| 指标 | SoT | 说明 |
|------|-----|------|
| 达人归因 GMV / 成交件 / 订单 | `fact_tiktok_affiliate_creator_daily` | 联盟中心 · 表现；`creator_id=handle` |
| 店级联盟 GMV / 动销达人数 / 预计佣金 | `fact_tiktok_affiliate_daily` | 同页店级 KPI |
| 是否出单 | `sold_flag` 或 `gmv>0 OR order_units>0` | 与动销达人卡片一致 |
| 已采投入 | **仅** `est_commission`（预计佣金） | 投流花费 / 寄样**金额**暂不采 → UI「— / 无数据」，**禁止填 0** |

**禁止：**

1. `达人归因 GMV + 广告 spend` 或 `+ 广告 revenue` 做「总生意」  
2. 用广告系列花费假填达人「投入」  
3. 用 ① 店日 GMV 或渠道「达人带货」**回填** ③ 表  
4. 把「近 7 天」窗均摊成 7 行自然日再环比  

**允许：**

- ① 若有渠道拆解「达人 / 联盟」占比 → 与 ③ 店级 `gmv_affiliate` **并排对照**（见 §3）  
- 达人行 `samples_shipped`（件数）可展示；**金额**仍无数据  

### 2.4 广告横切

| 指标 | SoT | 与 ③ 关系 |
|------|-----|-----------|
| 系列 spend / ROI / CPA / 展示·CTR | `fact_ads_campaign_daily` | **无**达人 id 关联前，**不得**按达人分摊 spend |
| 创意/组/素材 | 门禁未过不建表 | 不与 T7 混表 |

## 3. 对照（对账）策略 · 非互填

| 对照对 | 怎么用 | 差异怎么处理 |
|--------|--------|--------------|
| ① 店日 GMV vs 广告 revenue | 总览双卡；标源 | 差大 → 查日更/时区/退款，**不改**任一侧事实 |
| ① 渠道「达人带货」vs ③ `gmv_affiliate` | 有渠道列才对照 | 窗口/归因模型可能不同；只出「对照备注」，**禁止**用一侧覆盖另一侧 |
| ② 视频归因 GMV 合计 vs ① 店日 | 内容 TAB 注释 | 归因可重叠；不作等式 |
| ③ 达人 GMV 合计 vs ③ 店级 KPI | 同页应接近 | 明细截断（首屏 20 行）可导致合计 < 店级；以店级 KPI 为准看总量，明细看结构 |
| ③ 预计佣金 vs 达人 GMV | 规则可看背离 | 有佣金无 GMV → `creator_invest_no_sale`；**不是**用佣金反推 GMV |

**对账脚本原则（若写）：** 只读 SELECT + 告警，不 UPDATE 事实表。

|----|------|----------|

## 6. 异常域边界（避免重复出单语义混乱）

| code 前缀 / 域 | 只读事实 | 不读 |
|----------------|----------|------|
| `shop_*` | shop_daily | affiliate / content 归因 |
| `content_*` | content_daily | affiliate / ads spend |
| `creator_*` / `affiliate_*` | affiliate_* | ads spend、shop_daily GMV |
| `ads_*` | ads_campaign_daily | affiliate 佣金 |
| `product_*` | product 快照 | — |

同一经营现象（例如「店 GMV 跌」且「达人 GMV 跌」）**允许两域各出一条**，摘要写明域；运营按筛选处理，系统不做强制合并。

## 7. 一页禁令（给采集 / 同步 / 看板同事）

1. **不混加：** 达人归因 GMV ≠ 广告花费 ≠ 店日 GMV，三者不可加总成「总 GMV」。  
2. **不假填：** 无达人数据时留空；禁用 ads/shop 回填 affiliate。  
3. **不填 0 当无数据：** 投流花费、寄样金额未采 → `null` / UI `—`。  
4. **不拆窗：** 近 7 天是一条快照，不是 7 行日事实。  
5. **不占号：** 表 T7=达人日；页 **D4=联盟达人**；T5 财务表 / 已砍 AI 盘勿占。旧文 D5 作废。  
6. **creator_id = handle**（非平台内部 uid）；文档与 UNIQUE 已按此建。
