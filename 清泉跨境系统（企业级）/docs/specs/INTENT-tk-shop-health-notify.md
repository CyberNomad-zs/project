## §0 一句话

对 **stores.config 配置的全部 TK 店**：采集账号健康分、店铺体验分（含三模块）、达人健康评分（多账号）、1–2 星差评、达人新增违规；相对上次采集**任意变差/新增**则通知；通知通道为 **飞书企业应用私信宋敏 + 现有群机器人并存**；店铺体验分三模块写入**现有 TK 驾驶舱 Base 下新表**；提醒与进表**同一迭代交付**。

## §1 用户与场景

| 角色 | 场景 | 频率 |

| 运营/老板 | 群机器人同步看到同类提醒；多维表看体验分三模块趋势 | 日更 |

## §2 范围（L1 已确认）

| # | 决策 | 选择 |
|---|------|------|
| 1 店铺范围 | **B** | `stores.config`（及现网日更实际使用的主配置）内**全部 TK 店** |
| 2 下降/异常 | **A** | 比**上次成功采集快照**任意变差即提醒（与现网 `shop_health_drop` 口径一致：任意下降） |
| 3 与群提醒 | **B** | **私信宋敏 + 群 webhook 并存**（不关掉 `FEISHU_BOT_WEBHOOK_TK_HEALTH`） |
| 4 多维表 | **A** | 挂现有 **TK 驾驶舱 Base**，**新建一张表**承接体验分三模块 |
| 5 节奏 | **B** | 提醒能力 + 三模块进表 **同一 Ship-now** |

### In Scope（产品）

1. 账号健康分下降 / 过低（沿用并扩展通知通道）
2. 店铺体验分总分下降提醒
3. 达人健康评分（**切换账号列表内每个达人账号**）下降提醒
4. 商品评分新增 1★/2★ 差评提醒
5. 达人健康侧新增违规行为提醒（多账号）
6. 体验分三模块（商品满意度 / 履约物流 / 客户服务）→ 飞书多维表新表
7. 三模块分项任意变差 → 提醒（与 §2 决策 2 一致）
8. 企业应用 **im 私信**宋敏 + 群机器人双通道

### Out of Scope（本期明确不做）

1. 不做自动改价/改预算/代申诉等写操作
2. 不做 AMZ/Temu 同类能力
3. 不把 App Secret 写入仓库或飞书表
4. 不新建独立飞书 Base（只用现有 TK 驾驶舱 Base 加表）
5. 不要求 Web 任务台本迭代新做完整「体验分/达人健康」专页（异常任务列表可复用现有）

## §3 主流程（业务）

1. 采集机按店打开紫鸟 → 抓对应 Seller 页面  
2. 上报清泉 Ingest → PG 事实表  
3. 规则评估：对比上次快照 / 识别新增差评与违规  
4. 命中 → 写/刷新异常任务 + **群 webhook** + **App 私信宋敏**  
5. 体验分三模块 → 同步 TK Base 新表
