# L1 固定扫描维度（八维）

> PHASE 1 必读。缺则提问或标 `[ASSUMES: …]`。  
> 每轮 3–5 问；**安全 / 数据丢失 / 资金 / 权限 / 合规优先**。一次一问更稳。  
> 答案写入当前工作区 `docs/specs/` 下 SPEC 工作副本（模板见 `$SOP_ROOT/templates/SPEC.md`）。

---

## 使用方式

1. 对每一维标：`已明 | 缺口 | 假设 | N/A`
2. 缺口 → 列入本轮问题
3. 假设 → 写入 SPEC 的 ASSUMPTIONS
4. 扫完八维 → 填 SPEC + ACCEPTANCE → DoR 自检 → `SPEC READY` →（批准后）PHASE 2 MVP

同步加载：`$SOP_ROOT/skill-pack/01-req-clarify/SKILL.md`

---

## 维 1 — 用户与场景

| 探查点 | 示例问法 |
|--------|----------|
| 谁用？角色？ | 主要用户是谁？ |
| 何时用？频率？ | 例行还是偶发？ |
| 现状替代什么？ | 手工 / 旧系统 / 不存在？ |
| 场景边界 | Web / 移动 / API / 是否离线？ |

**可测输出**：主用户角色 ≥1；核心场景 ≥1 段。

---

## 维 2 — 目标与成功标准

| 探查点 | 示例问法 |
|--------|----------|
| 要解决的问题 | 不做会怎样？ |
| 成功长什么样 | 怎样算做成？（数字/可勾选） |
| 非目标 | 这次**明确不追求**什么？ |

**禁止**：仅「体验更好 / 更智能」而无观测方式。  
**可测输出**：≥1 条可观测成功标准。

---

## 维 3 — 范围边界

| 探查点 | 示例问法 |
|--------|----------|
| In Scope | 第一期必须有哪些能力？ |
| Out of Scope | 明确不做哪些？（**至少 3 条**） |
| 依赖他人 | 是否依赖别的团队/系统先就绪？ |

**可测输出**：In 列表；**Out ≥ 3**。

---

## 维 4 — 主流程与异常流

| 探查点 | 示例问法 |
|--------|----------|
| Happy path | 从开始到完成的主路径？ |
| 失败路径 | 失败时用户看到什么？能否重试？ |
| 边界 | 空数据、超时、并发、权限不足？ |

**可测输出**：主流程步骤；**Edge ≥ 3**；每主功能 ≥1 happy + ≥1 error AC。

---

## 维 5 — 数据与权限

| 探查点 | 示例问法 |
|--------|----------|
| 读写哪些实体 | 核心业务对象是什么？ |
| 谁可见/可改 | 角色与权限？ |
| 敏感数据 | 是否含 PII / 密钥 / 财务数据？能否进日志/Prompt？ |
| 保留与删除 | 删除策略？谁有权？ |

**可测输出**：数据对象列表；权限一句话；敏感数据约束。

---

## 维 6 — 集成依赖

| 探查点 | 示例问法 |
|--------|----------|
| 外部系统 | 支付、消息、身份、对象存储、内部中台等？ |
| 契约 | 已有 API 文档还是待定？ |
| 失败降级 | 下游挂了是否允许排队/降级？ |

**可测输出**：依赖列表（无则写「无外部依赖」）；关键失败策略。

---

## 维 7 — 非功能

| 探查点 | 示例问法 |
|--------|----------|
| 多语言 / 时区 | 需要吗？ |
| 多币种 / 计量单位 | 需要吗？ |
| 性能 | 可接受的延迟/吞吐？ |
| 审计 | 是否需要操作日志？保留多久？ |
| 环境 | 内网 / 公网 / 多区域？ |

**可测输出**：NFR 表（不适用填 N/A）。

---

## 维 8 — 合规与发布边界（最短表）

> 适用则填写；不适用则整维 **N/A + 一句理由**。  
> 展开项：[`templates/spec-compliance-checklist.md`](../../../templates/spec-compliance-checklist.md)

| # | 项 | 必问 | 填写 |
|---|----|------|------|
| 8.1 | 目标区域/租户/环境 | 覆盖哪些区域或租户？ | |
| 8.2 | 外部平台/渠道 | 依赖哪些第三方平台或渠道？ | |
| 8.3 | 资金与计量 | 是否涉及支付、结算、计量计费？ | |
| 8.4 | 法规与策略红线 | 隐私、行业监管、内容/业务红线？ | |
| 8.5 | 审计与可追溯 | 关键动作是否要留操作者/对象/时间日志？ | |
| 8.6 | 数据驻留与跨区 | 数据存放位置与跨区/跨司法辖区限制？ | |
| 8.7 | AI 披露 | 对用户是否需披露 AI 生成/AI 代理？ | |
| 8.8 | 授权范围 | 自动化操作是否需明确授权边界？ | |
| 8.9 | 发布策略 | 全量还是灰度/分批？回滚策略？ | |

**可测输出**：上表每项有值或 N/A；触及资金/凭据/法定字段 → 标 G3 风险。

---

## 澄清轮次建议

```text
Round 1: 维1–3（人、目标、范围）
Round 2: 维4–5（流程、数据）
Round 3: 维6–8（集成、NFR、合规与发布）
然后: SPEC 草稿 → 阻断级 Open Questions → DoR / check-dor → SPEC READY → MVP READY
```

## 假设语法

```text
[ASSUMES: 第一期仅支持单一区域；未确认前不做多区域]
```
