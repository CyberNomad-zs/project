# 清泉跨境系统 · 架构方案

> 版本：v1.1  
> 日期：2026-07-28  
> 依据：技术会.xmind + 海外仓 / Temu 监测 / TK 广告 三项目盘点  
> 产品组织视角补充：[中台产品蓝图.md](./中台产品蓝图.md)（来源 `中台.xmind`，2026-07-28）

## 1. 背景与目标

### 1.1 业务目标

建设企业私有化定制平台，汇总 **TikTok Shop、Temu、Amazon** 等电商平台运营数据，支撑：

- 平台销售异常 / 账号异常监控与跟踪任务
- 采购侧供应商、滞销断货、销售天数
- 数据落 **线上数据库**，并 **同步导出到飞书多维表格**
- 以 **企业智能体** 为主通道发送通知（会议红标重点）

### 1.2 现有资产

| 项目 | 路径 | 形态 | 数据落点 | 可复用 |
|------|------|------|----------|--------|
| 海外仓 | `E:\project\海外仓` | Python + Sellfox OpenAPI + WMS + SQLite | 本地 bridge.db | 赛狐鉴权、包裹流水线、WMS、飞书告警 |
| Temu 监测 | `E:\project\temu` | Chrome MV3 + Node/Playwright | 本地 JSON | 后台 hook、赛狐商品、多店、飞书卡片 |
| TK 广告 | `E:\project\海外TK店铺广告投流数据自动化监测` | Chrome MV3 + 紫鸟 CLI + PS | 飞书多维表 | DOM/API 抓取、Bitable 写入、日报、紫鸟编排 |

共性：本机常驻 + 浏览器登录态 + 飞书触达。  
缺口：无统一在线库、无统一任务引擎、无 Web 管理端。

### 1.3 架构跃迁

| 维度 | 现在 | 目标 |
|------|------|------|
| 存储 | 本机 JSON / SQLite / 直写飞书 | **PostgreSQL 为 SoT**，飞书为同步出口 |
| 采集 | 三套独立脚本/插件 | 统一 Collector Agent + 平台适配器 |
| 业务 | 告警为主 | 监控 → 任务闭环 → 运营看板 |
| 部署 | 个人 PC 计划任务 | 中心服务 + 边缘采集节点 |

## 2. 总体架构

### 2.1 逻辑分层

```
接入层   Web 管理端 │ 飞书多维表/机器人 │ 企业智能体 │ 邮件 │ OpenAPI
应用层   运营监控 │ 任务引擎 │ 采购 │ 产品中心 │ 报表/导出 │ 权限组织
领域层   异常判定 │ 去重/状态机 │ 调度 │ 飞书同步器 │ 通知编排
数据层   PostgreSQL │ Redis │ 对象存储 │ 消息/Outbox
采集层   Amazon插件 │ Temu插件/Monitor │ TK+紫鸟 │ 赛狐 Worker │ 海外仓 Bridge
```

### 2.2 部署拓扑

```
              ┌─────────────────────────┐
              │  中心（固定 IP / 内网）    │
              │  API + Web + PG + Redis  │
              │  Scheduler + Worker      │
              └───────────┬─────────────┘
                          │ HTTPS
     ┌────────────────────┼────────────────────┐
     ▼                    ▼                    ▼
采集机A（白名单IP）   采集机B（运营PC）      紫鸟环境
赛狐 API Worker      Amazon/Temu 插件       TK 多店 RPA
```

**原则**

1. 中心无头可集群；采集因登录态 / IP 白名单必须边缘化。
2. 插件 **不直连数据库**，只调中心 Ingest API。
3. 赛狐 Worker 与现有海外仓机器可共用固定出口 IP。

### 2.3 技术选型

| 层级 | 选型 | 说明 |
|------|------|------|
| 后端 | Python 3.12 + FastAPI | 复用海外仓 Python 资产 |
| 队列 | ARQ 或 Celery + Redis | 定时拉取、异步写飞书 |
| 主库 | PostgreSQL 16 | SoT；JSONB 兼容平台差异 |
| 缓存 | Redis 7 | 锁、调度、token |
| 前端 | Vue 3 + Element Plus | 中后台快速交付 |
| 插件 | Chrome MV3 | 改造现有三套 |
| TK 多店 | 紫鸟 + ziniao-cli | 已稳定，封装 Collector |
| 对象存储 | MinIO 或本地盘 | 巡检截图 |
| 飞书 | 自建应用 + Bitable + 机器人 | 从 TK 项目抽公共库 |
| 部署 | Docker Compose | 私有化单机首选 |
| 鉴权 | JWT + RBAC | 店铺数据权限 + 供应商脱敏 |

## 3. 核心子系统

### 3.1 统一采集（Collector）

```
collectors/
├── agent-core/          # SDK：鉴权、心跳、上报、重试
├── sellfox-worker/      # 源自海外仓 sellfox 客户端
├── amazon-extension/    # 前台巡检 12 项（新建）
├── temu-extension/      # 改造自 temu-plugin
├── temu-monitor/        # 改造自 temu-monitor
└── tiktok-ads/          # 改造自 TK 项目
```

上报统一报文：

```json
{
  "source": "tiktok_ads",
  "platform": "tiktok",
  "shop_id": "27501502216807",
  "shop_name": "Deal to deal",
  "biz_date": "2026-07-26",
  "collected_at": "2026-07-27T17:20:00+08:00",
  "idempotency_key": "tiktok_ads:27501502216807:拖把7/13:2026-07-26",
  "payload": {},
  "evidence": { "screenshot_url": null, "source_url": "..." }
}
```

`idempotency_key` 唯一约束 → 支持重跑不脏数据。

### 3.2 任务引擎（会议规则）

**去重键：** `platform + biz_id + anomaly_type`（如 ASIN + 异常类型）

**状态机：**

```
检出异常
  ├─ 存在未闭环同键任务 → 只更新进度/数据
  └─ 否则 → 新建任务，指派第一负责人，写截止时间
IN_PROGRESS
  ├─ 每日固定提醒
  ├─ 人工推进进度
  └─ 异常消失 → RESOLVED（闭环）
闭环后再次出现 → 新建（不复活旧单）
```

**账号异常：** 仅异常建任务，正常静默。

### 3.3 调度（对齐会议）

| Job | 时间 | 说明 |
|-----|------|------|
| 亚马逊销售异常 | 每日 07:00 | 拉昨日 |
| 亚马逊账号异常 | 05:30 起每 8h，3 次/日 | 前台 + 绩效 |
| 采购销售天数 | 每周一 07:00 | 赛狐 |
| TK 广告 | 17:20 | 沿用现网，业务日=昨日 |
| Temu 监测 | 15min + 09:30/16:30 必提醒 | |
| 飞书同步 | 5–15min 或事件驱动 | |
| 库存快照 | 日级 | FBA + FBM/WMS |

### 3.4 飞书同步器

- PostgreSQL = Source of Truth  
- 飞书 = 协作视图 + 告警通道  
- 维护 `sync_feishu_map(local_id ↔ record_id)`，支持 **update**，禁止只 append 导致重复  
- 字段别名映射（复用 TK 项目逻辑）

建议多维表：

| 表 | 受众 |
|----|------|
| 运营_销售异常跟踪 | 运营 |
| 运营_账号健康 | 运营 |
| TK_广告日报 | 投流 |
| Temu_流量与下架 | Temu |
| 采购_滞销断货 | 采购 |
| 采购_供应商（脱敏） | 全员 |

### 3.5 通知编排

```
领域事件 → Router
  ├─ 企业智能体 IM（主通道）
  ├─ 飞书群机器人
  └─ 邮件（采购试行）
收敛：同负责人 N 分钟合并；必提醒可非异常汇总
```

### 3.6 权限与脱敏

- 用户 → 部门 → 授权店铺  
- 角色 `procurement_full` 可见供应商名称；其余 API 强制 `name → code`  
- 采集端使用设备级 API Key + 店铺范围

## 5. 分期路线

| 阶段 | 周期 | 交付 |
|------|------|------|
| Phase 0 | 2–3 周 | Docker 基座、Ingest、任务状态机、飞书同步 MVP、登录/店铺主数据 |
| Phase 1 | 2–3 周 | TK 广告上云、Temu 监测上云、赛狐只读 SDK；**AMZ 环比异常→人维任务样板**（见中台蓝图） |
| Phase 2 | 3–4 周 | 亚马逊销售异常 + 账号巡检 12 项 + FBA；FBM 接 WMS；**巡店插件 + 补货审批** |
| Phase 3 | 3–4 周 | TK 运营扩展、Temu 物流/链接、采购供应商/滞销/邮件；**美工任务推送** |
| Phase 4 | 持续 | 看板、智能体查数催办、规则 UI、发货域评估并入；**老板驾驶舱 + 财务五表** |

产品域（采购/财务/美工/老板驾驶舱）与导航目标详见 [中台产品蓝图](./中台产品蓝图.md)。

## 7. 非功能

| 项 | 策略 |
|----|------|
| 幂等 | ingest / task 去重键落 DB 唯一约束 |
| 安全 | 密钥环境变量；插件范围 Key；供应商脱敏 |
| 审计 | 闭环、导出、权限变更 |
| 备份 | PG 日备；飞书不做备份源 |
| 可观测 | 采集成功率、任务 SLA、同步延迟 |
| 平台合规 | 优先官方/赛狐 API；前台巡检控频（3 次/日） |
