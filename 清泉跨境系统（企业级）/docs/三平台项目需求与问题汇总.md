## 一、Temu 项目（`E:\project\temu`）

### 1.1 业务场景

金猫商贸 Temu 多店（Agnis / HomeCove / Twilight Cove）的 **商品运营健康监测**。

### 1.2 核心需求

| 需求 | 说明 |
|------|------|
| 在售监控 | 在售数量下降时，点名具体下架商品 + 编辑链接 |
| 流量异常 | 「商品流量待关注」增加、「近期有下降」变多时告警 |
| 多店轮巡 | 同一账号下多店自动切换巡检 |
| 实时通知 | 异常推飞书；支持定时必提醒（确认监测还在跑） |
| 下架点名 | 结合赛狐 OpenAPI（`selectStatus` 离开在售）补齐下架明细 |

### 1.3 解决了什么问题

1. **人工盯后台成本高**：运营不用每几分钟打开 Temu 后台看列表。
2. **下架/限流发现滞后**：异常时飞书直接点名商品 + 链接，可马上处理。
3. **多店难兼顾**：插件/守护进程自动轮巡三店，避免漏店。
4. **登录与会话复用**：插件复用日常浏览器登录态；Playwright 版支持本机常驻。

### 1.4 实现形态

| 形态 | 路径 | 说明 |
|------|------|------|
| Chrome 插件 | `temu-plugin/` | 早期主力，装在日常浏览器 |
| Node + Playwright 守护 | `temu-monitor/` | 无需插件；全量对齐插件能力（赛狐下架 + 浏览器流量/在售 + 飞书） |

### 1.5 主要能力清单

1. 下架点名（赛狐 OpenAPI，`selectStatus` 离开在售=12）+ 编辑链接  
2. 商品流量待关注增加 + 商品明细链接  
3. 商品流量近期有下降增加 + 商品明细链接  
4. 在售数量变化（浏览器 countStatus）  
5. 多店轮巡（会话级切店）  
6. 飞书告警、登录过期提醒

## 二、TikTok 项目（`E:\project\海外TK店铺广告投流数据自动化监测`）

### 2.1 业务场景

TikTok 英区店铺 **广告投流数据** 的自动抓取、汇总与日报。

### 2.2 核心需求

| 需求 | 说明 |
|------|------|
| 自动抓取 | 每日定时从各店广告后台拉 5 个核心字段 |
| 核心字段 | 广告系列名称、广告花费、销量、ROI、总收入 |
| 多店汇总 | 多店数据写入同一飞书多维表，可按店/日期对比 |
| 日报自动化 | 抓完自动生成总览、分店 KPI、亮点、低 ROI 风险、TOP 系列 |
| 安全环境 | 在紫鸟浏览器独立环境中执行，避免关联与密码硬编码 |

### 2.3 抓取字段

| 字段 | 说明 |
|------|------|
| 广告系列名称 | Campaign / 品名 |
| 广告花费 | Spend / Cost |
| 销量 | Orders / Units |
| ROI | ROI / ROAS |
| 总收入 | GMV / Revenue / 销售额 |

另附：业务日期、店铺、抓取时间、数据源 URL、状态。

### 2.4 解决了什么问题

1. **日报人工苦力**：原先要逐店登录、导出、整理，耗时易错。
2. **数据分散难对比**：统一进飞书表，跨店横向看花费/销量/ROI。
3. **运营决策前置**：日报自动标低 ROI、零产出花费、失败店，先抓风险再深入分析。
4. **店铺扩容**：店铺列表从紫鸟动态拉取，新店命中规则即自动纳入，不用改代码。

### 2.5 实现形态

- 紫鸟「卖家自研插件」抓取 TikTok 广告页（DOM 表头语义匹配 + fetch/XHR 报表兜底）
- PowerShell 多店串行（`run-multi-store.ps1`）+ Windows 定时任务
- 飞书多维表落库 + `日报/` 目录 Markdown / 简报 / JSON
- 图形启动器（`gui.py` / `美化启动器.bat`）

### 2.6 日报分析产出

1. **总览**：成功店数、系列数、花费/销量/销售额合计、综合 ROI  
2. **分店汇总**：每店系列数与 KPI、贡献 TOP 系列  
3. **亮点**：销售额最高店、ROI 最高店、单系列 TOP  
4. **风险**：综合 ROI 低于阈值、花费>0 销售额为 0、抓取失败店  
5. **系列 TOP**：按销售额 / 按 ROI

## 三、海外仓项目（`E:\project\海外仓`）

### 3.1 业务场景

**接单（赛狐 ERP）→ 英国海外仓履约（WMS）→ 回传平台** 的发货自动化。

- 服务客户：金猫商贸  
- 白名单店：Agnis / HomeCove / Twilight Cove（Temu 侧）  
- WMS 分 **金猫 / 黑猫** 两套账本  

### 3.2 核心需求

| 需求 | 说明 |
|------|------|
| 自动发现待处理包裹 | 只处理白名单店，禁止误动同账号其它店 |
| 渠道保留/人工指派 | 有渠道则保留；无渠道告警转人工，不乱自动选 |
| 自动物流下单 | 触发赛狐「物流下单」推到 WMS |
| 出库后回传闭环 | WMS 已发货 + 运单号 → 回传赛狐（有重量称重，无重量 quick 出库） |
| 双仓路由 | 昇新渠道 → 金猫 WMS；BLACKCAT → 黑猫 WMS |
| 对账与告警 | 每日对账近 7 天运单/承运商；失败/严重差异飞书推群 |

### 3.3 解决了什么问题

1. **网页自动化不稳**：旧方案模拟点「物流下单/发货」，易卡验证码、改版挂、会话失效。
2. **金猫/黑猫易串号**：API 分账本路由，降低错仓错发风险。
3. **漏推仓 / 漏回传**：状态机防重下单 + 出库后自动回传 + 日对账暴露差异。
4. **人工盯盘负担**：约 5 分钟一轮轮询，缩短「待处理 → 推仓」响应；成功不刷屏，异常才告警。

### 3.4 实现形态（演进）

| 方案 | 路径 | 定位 |
|------|------|------|
| Playwright 网页自动化 | `automation/` | 早期方案，现作参照 |
| 浏览器扩展 | `extension/` | 真实会话里按渠道串行 ERP→WMS |
| **API 桥接（主用）** | `sellfox-bridge/` | 赛狐开放 API + WMS API，三店 G2 已验收常驻 |

### 3.5 流水线（sellfox-bridge）

| 步骤 | 做什么 | 说明 |
|------|--------|------|
| step1 | 拉 `to_process` | 白名单店铺；FAILED 有渠道可复活 |
| step1b | 拉 `apply_track_no` | 已下单 → 本地同步 `ORDERED`（防重复下单） |
| step2 | 认渠道 | 有渠道则保留；无渠道人工指派 → FAILED |
| step3 | 物流下单 | `auto_apply_track_no: true` 时 `applyTrackNo` |
| step4 | 回传 | 对应 WMS 已发货+运单 → 有重量称重，否则 quick 出库 |

本地状态机：`NEW → CHANNEL_ASSOCIATED → ORDERED → CLOSED`（失败 → `FAILED`，陈旧 → `STALE`）。

### 3.6 范围边界（明确不做）

| 不做项 | 原因 |
|--------|------|
| 仓内拣货/改快递/批量发货 API 化 | WMS 对客户开放接口以查询为主；本期目标是稳定「交运+回传」 |
| 非白名单店铺 | 同赛狐账号下存在其它 WMS 客户店铺，误开会造成错账、错发 |
| 待审核地址修剪/拆包全自动 | 缺品类主数据；部分能力赛狐无地址编辑 API，需二期专项 |

## 四、总览对照

| 维度 | Temu | TikTok（海外TK） | 海外仓 |
|------|------|------------------|--------|
| **平台侧** | Temu 卖家后台 | TikTok Shop 广告后台 | 赛狐 ERP + 英国 WMS（服务 Temu 等出单） |
| **业务焦点** | 商品在售 / 限流 / 下架 | 广告花费·ROI·销量日报 | 订单发货闭环 |
| **核心痛点** | 异常发现慢、多店难盯 | 日报人工导出汇总 | 点单不稳、串仓、漏回传 |
| **核心产出** | 飞书异常告警 + 商品链接 | 飞书明细表 + 自动日报 | 自动下单/回传 + 对账告警 |
| **技术栈** | 插件 / Playwright + 赛狐 API | 紫鸟插件 + PS 多店 + 飞书 | Python API 桥（主）+ 扩展/自动化（旧） |
| **通知** | 飞书 Webhook | 飞书多维表 | 飞书失败/对账告警 |
| **源码路径** | `E:\project\temu` | `E:\project\海外TK店铺广告投流数据自动化监测` | `E:\project\海外仓` |

## 五、一句话总结

1. **Temu**：自动盯「有没有下架、有没有被限流」，有问题立刻飞书点名。  
2. **TikTok**：自动抓广告核心指标进飞书并出日报，替代每日手导出。  
3. **海外仓**：用 API 把「赛狐待处理 → 推海外仓 → 出库回传」跑通，替代不稳的网页点单。
