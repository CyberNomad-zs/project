## 1. BRIEF — 问题与目标

### 1.1 原始需求

- INTENT：`docs/specs/INTENT-tk-shop-health-notify.md`
- raw：`docs/specs/INTENT-raw-tk-shop-health-notify-20260811.md`
- 源：`TikTok shop需求.docx`

```text
飞书企业应用私信宋敏：
1) 账号健康分 / 店铺体验分 / 达人健康评分 下降提醒（达人多账号）
2) 商品评分新增 1★、2★ 差评提醒
3) 达人健康新增违规提醒（多账号）
4) 店铺体验分三模块进飞书多维表，且异常时提醒

L1 确认：全 stores.config 店；任意变差；私信+群并存；TK Base 新建表；提醒与进表同迭代。
```

### 1.2 问题陈述

- 运营需盯多个 Seller 页（账号健康、体验分、达人健康切换账号、差评、违规），人工滞后。
- 现网仅 **账号健康分 + 店铺违规 + 差评** 进 PG，通知主要为 **群机器人**；缺体验分/达人健康多账号；无 App 私信宋敏。
- 不做则：分数下滑、差评、达人违规发现晚，体验分无台账。

### 1.3 目标用户与场景

| 角色 | 场景 | 频率 |
|------|------|------|
| 宋敏 | 飞书私信收告警并跟进 | 日更后有命中时 |
| 运营群 | 群机器人同步告警 | 同上 |
| 运营 | 飞书多维表看体验分三模块历史 | 日更后 |

### 1.4 成功标准（可观测）

- [ ] 主配置内全部 TK 店完成：健康 / 体验分 / 达人健康（多账号）/ 差评 / 达人违规 的采集→PG（或明确跳过原因进日志）
- [ ] 相对上次快照任意变差或新增差评/违规时，**同一事件**同时尝试：异常任务落库 + 群 webhook + App 私信宋敏（通道可配置开关，默认双开）
- [ ] 体验分三模块写入 TK 驾驶舱 Base **新表**，字段可在飞书 UI 核对
- [ ] App Secret 与宋敏身份 ID 仅来自环境变量，不进 git

### 1.5 非目标（Non-goals）

- 不自动申诉、不代回复差评、不改店铺设置
- 不覆盖 AMZ/Temu
- 不新建独立飞书 Base
- 本迭代不强制全新 Web 专页（复用异常任务/现有任务台即可）

## 3. 主流程

### 3.1 Happy path

1. 日更脚本按 stores.config 逐店：health / experience / creator_health(多账号) / reviews / creator_violation  
2. Ingest 幂等写入事实表  
3. 批末或 ingest 后评估规则  
4. 命中 → upsert 异常任务 → 发群 → 发私信  
5. 体验分三模块行 → 飞书新表 upsert  

### 3.2 异常与边界（≥3）

1. 某店页面未登录/SPA 未就绪 → 该模块失败，记日志，他店继续  
2. 无私信 user_id → 跳过私信，群与任务仍成功  
3. 无上次快照 → 不触发「下降」类；仍可触发「低分≤150」「新增差评/违规」  
4. 飞书表同步失败 → PG 保留，任务可标 sync_error，下次重试  
5. 达人列表为空 → 记 warning，不伪造成功  

### 3.3 规则口径（L1：2A）

| 对象 | 触发 |
|------|------|
| 账号健康分 | 较上次任意下降 **或** ≤ `TK_HEALTH_LOW_THRESHOLD`（默认 150） |
| 店铺体验分总分 | 较上次任意下降（含 0.1 级小数） |
| 三模块分项分数/关键率 | 较上次任意变差（数值变差方向按指标语义：分↓坏、取消率↑坏等）`[ASSUMES: 方向表在实现 Plan 固化]` |
| 达人健康分 | 每达人账号较自己上次任意下降 |
| 差评 | 新出现 rating≤2 的评价（对齐现网窗口/是否仅未回复配置） |
| 达人违规 | 该达人账号维度首次出现的违规记录（或 first_seen 在窗口内） |

通知去重：未闭环同 dedupe 仅刷新；**指标继续恶化**才再推送（对齐现网健康分）。

## 4. 数据与权限

### 4.1 核心对象

| 对象 | 说明 |
|------|------|
| fact_tiktok_health_daily | 已有账号健康 |
| fact_tiktok_experience_daily（新） | 体验分总分 + 三模块摘要 + raw |
| fact_tiktok_creator_health_daily（新） | 店 × 达人账号 × 日 |
| fact_tiktok_creator_violation（新或扩展） | 达人违规明细 |
| fact_tiktok_review / violation | 已有差评/店违规 |
| fact_tk_anomaly_task | 异常任务 |
| 飞书新表 | 体验分三模块日行 |

### 4.2 权限

- 采集：采集机本地 + Ingest API Key  
- 飞书：应用权限含 `im:message` 私信；多维表读写现网 token  
- 管理端：现有 admin JWT 即可查异常（若暴露 API）

### 4.3 敏感数据

- App Secret、webhook、user_id → **仅 env**  
- 差评用户名可进 PG/飞书运营表；禁止把 Secret 打进日志全文
