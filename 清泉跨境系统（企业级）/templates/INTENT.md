# INTENT — 结构化需求整理稿

> **角色：AI 产品经理 / BA / 需求整理者填写。**  
> **不要**把本表直接甩给甲方当问卷。  
> 甲方收集请用：[`INTENT-raw.md`](./INTENT-raw.md)（白话收集卡）。  
>  
> 本表是 `/ai-dev-sop` 的**推荐入口物料**（整理后的 Intent），**不是**最终 Spec。  
> 不会写 / 不确定 → 填 **`未知`**，不要编。

---

## 分层说明（必读）

```text
甲方 / 业务          →  templates/INTENT-raw.md     （白话、可口述）
AI 产品经理整理      →  templates/INTENT.md          （本文件）
Agent + 人门禁       →  SPEC / ACCEPTANCE            （L1 之后）
```

### 整理者工作流

1. 收齐 `INTENT-raw` 或会议/聊天原话  
2. 填本表（至少 **§0 极速卡**）  
3. 对话启动：

```text
/ai-dev-sop

请按 AI 开发 SOP 从 L1 开始。以下是 INTENT（已由产品整理）：

<粘贴本文件全文>
```

4. Agent 做八维扫描与澄清 → 出 SPEC；**人批准 Spec 后才写码**

## §0 极速卡（最少必填 · 约 5～10 分钟）

| # | 字段 | 你的填写 | 提示 |
|---|------|----------|------|
| 0.1 | **一句话目标** | | 写**结果**，少写方案。例：「让运营 3 分钟内定位订单卡在哪」 |
| 0.2 | **谁会用** | | 角色，不是人名 |
| 0.3 | **典型场景** | | 何时、在哪、触发什么 |
| 0.4 | **痛点 / 动机** | | 现状、摩擦、不做的后果 |
| 0.5 | **怎样算做成** | | **可观测**；禁「更好用」 |
| 0.6 | **明确不做** | 1. … 2. … 3. … | 理想 ≥3 条；未知则写「未知，待澄清」 |
| 0.7 | **开工类型** | 见下方选项 | 整理者填写；来自 raw 第 8 题映射 |
| 0.8 | **时间盒 / 紧急度** | | 演示节点 / 上线窗口 / 无硬截止 |
| 0.9 | **硬约束或红线** | | 栈、环境、禁区、安全；无则写「无」 |
| 0.10 | **整理人 / 日期** | | |
| 0.11 | **原始来源** | | 例：`docs/specs/INTENT-raw-xxx.md` / 会议纪要链接 |

### 0.7 开工类型（写给人看 + 映射给流程）

先选**白话**，再在括号里保留流程枚举（给 Agent / SOP 用）：

| 白话（整理时勾选） | 写入 0.7 的推荐写法 | SOP 枚举 |
|--------------------|---------------------|----------|
| 改已有系统/功能 | `改已有系统（feature）` | `feature` |
| 从零做新项目/新服务 | `从零新建（greenfield）` | `greenfield` |
| 暂不确定 | `未知` | `未知` |

> **不要让甲方填 feature/greenfield。** 由整理者根据 raw 第 8 题映射。

### 0.x 一句话版（可选压缩）

```text
【谁】在【场景】下，因【痛点】，要【可观测结果】；
不做【…】；约束【…】；截止【…】；类型【改已有/从零/未知】。
```
