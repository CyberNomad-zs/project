## 4. 运营需要 vs 当前可抓

| 优先级 | 需要的数据 | 当前紫鸟页能否抓 |
|--------|------------|------------------|
| P0 | 店×计划×日：花费/订单/收入/ROI/开关 | ✅ 已抓（脚本） |
| P0 | 业务日、店铺 ID/名 | ✅ 脚本侧补 |
| P1 | 店级汇总 KPI + 7 日环比 | ✅ 页上有，脚本可加 |
| P1 | 日预算、目标 ROI、状态文案、平均下单成本 | ✅ 列表已有列，脚本未取 |
| P2 | 订单明细 / 商品 / 履约 / 财务 | 需**另开对应菜单页**再写抓取 |
| P2 | 账号健康分 | 需打开「账号健康」页 |

## 5. 结论

1. **广告 GMV Max 面板**字段远多于现网 5 字段，P1 可继续在同一页扩列。  
2. **日常运营核心**（花费、单、收入、ROI）已覆盖。  
3. **非广告数据**不能靠这一页一次抓全，要按导航分模块开店抓取。  
4. 采集必须继续走 **紫鸟**，禁止本机浏览器直连卖家后台。
