## 4. 常用核对 SQL（生产/本机通用）

```sql
-- 对象
SELECT table_schema, table_type, table_name
FROM information_schema.tables
WHERE table_schema IN ('public','tk','temu')
ORDER BY 1,2,3;

-- 行数
SELECT 'tk.fact_tiktok_order' t, count(*) FROM tk.fact_tiktok_order
UNION ALL SELECT 'tk.fact_ads_campaign_daily', count(*) FROM tk.fact_ads_campaign_daily
UNION ALL SELECT 'public.ingest_raw', count(*) FROM public.ingest_raw
UNION ALL SELECT 'public.task', count(*) FROM public.task;

-- 采集源
SELECT source, process_status, count(*), min(received_at), max(received_at)
FROM ingest_raw GROUP BY 1,2 ORDER BY 1;

-- 订单质量
SELECT count(*) FILTER (WHERE biz_date > CURRENT_DATE) AS future_biz_dates,
       min(biz_date), max(biz_date),
       count(DISTINCT shop_external_id)
FROM tk.fact_tiktok_order;

-- 店名对齐
SELECT s.external_shop_id, s.name AS master_name,
       f.shop_name AS fact_name, count(*)
FROM tk.fact_tiktok_order f
LEFT JOIN shop s ON s.external_shop_id = f.shop_external_id AND s.platform='tiktok'
GROUP BY 1,2,3;
```

## 5. 缺口与建议（跨环境）

| 优先级 | 项 | 建议 |
|--------|----|------|
| P0 | 生产订单未来 `biz_date` | 查采集端时区/支付日解析；必要时回填校正 |
| P0 | 店名/ID 映射 | 统一 `shop` 主数据与紫鸟展示名（alias_names） |
| P1 | 商品/KPI/健康/财务 | 接 scrape + ingest（表与 API 已就绪）；**广告日更定时已在同事本机**，中心不重建 |
| P1 | 生产无 task 闭环 | 规则引擎/低 ROI 等对生产广告·订单开启前先小流量 |
| P1 | 飞书未接 | outbox/worker + bitable token |
| P2 | `007_qq_namespaced_facts` 漂移 | 与仓库对齐：合入 git 或服务器删除；避免双 007 |
| P2 | 无 `schema_migrations` 表 | 增加版本记录，避免「文件在、表不在」 |
| P2 | `temu` schema | 同事并库时再 `CREATE SCHEMA` |
| 注意 | 本机≠生产数据 | 汇报行数务必标明环境 |
