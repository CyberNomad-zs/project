## §1 问题与工作

### 1.1 问题陈述

- **As-Is**：异常 → 任务 → `task_progress.note` 自由文本闭环；无统一动作码、无效果标签、无「同类异常有效动作」视图
- **摩擦点**：同类环比下跌/广告风险/健康项反复出现时，只能问老人或翻聊天记录
- **To-Be**：`(platform, anomaly_type) → [action] → [effect/outcome]` 可沉淀、可排序、可在任务流中指导下一步

### 1.2 核心对象（草案，待确认）

| 对象 | 说明 |
|------|------|
| 异常类型 | 已有 `anomaly_type`（如 `link_wow_units_drop` / `tiktok_risk` …） |
| 运营动作 | 结构化 `action_code` + 可选参数/备注（升级自由 note） |
| 效果 | 任务关闭后的 outcome 标签 和/或 指标恢复观测（如 N 日后 units 回升）— **待确认** |
| 知识条目 | 策展后的 playbook：适用条件 + 推荐动作序列 + 证据（样本量/成功率） |

### 1.3 成功标准草稿（待确认后写入 SPEC）

| ID | 草稿 | 状态 |
|----|------|------|
| S1 | 运营打开某 anomaly 任务时能看到 ≥1 条「历史有效动作」或官方剧本 | 待确认 |
| S2 | 闭环时必须（或可）选 action_code + effect_label | 待确认 |
| S3 | 按 platform+anomaly_type 可统计 Top 动作与效果分布 | 待确认 |
| S4 | 知识词条可人工策展与版本/启停 | 待确认 |

## §2 范围直觉（未冻结）

### 2.1 可能 In（候选）

1. 动作码字典 + 效果标签字典  
2. 任务进度/闭环写入结构化三元组  
3. 按异常类型检索与统计

2. 大模型自由对话知识库（RAG）作为 1.0 必交  
3. 跨租户/跨公司知识市场  
4. 替换现有 task 状态机  
5. 财务/采购域知识  

### 2.3 依赖

- 任务引擎与 anomaly 建单已就绪（Phase0 / AMZ 环比草案）  
- 效果若绑指标恢复：依赖 `fact_*` 日指标与可观测窗口

## §3 主流程草案（待确认）

```text
异常命中 → 建/更任务
  → 打开任务：展示本 anomaly_type 知识/历史 Top 动作
  → 执行者选 action_code（+ note）推进
  → 闭环：填 effect / 系统 N 日后回填指标效果
  → 聚合统计 →（可选）生成词条草稿 → 人审发布 → 反哺推荐
```
