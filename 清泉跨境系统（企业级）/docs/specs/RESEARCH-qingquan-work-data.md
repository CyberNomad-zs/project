# RESEARCH — 员工监督 / 过程与自创数据：方向调研

> 日期：2026-07-28  
> 用途：喂给 INTENT / SPEC（非最终 Spec）  
> 输入：参考材料（流程图、三平台汇总）+ 联网调研 + 业务差异化（监督 / 记录学习 / 自创过程数据）  
> 约束：1.0 必须做到 **存得住+查得到（A）** 与 **按人/按事复盘（B）**；**建议/自动规则（C）** 仅架构预留，待 1.0 积累后再做

---

## 1. 变革定位（传统跨境外贸公司 → 可学习运营组织）

| 旧范式 | 新范式（你们要的） |
|--------|-------------------|
| 看平台报表 / ERP 官方数据 | 看「人有没有做事、怎么做、结果如何」 |
| 异常靠飞书喊一声 | 异常变成**工单/案件**，有负责人、SLA、闭环 |
| 经验在老人脑子里 | 处置过程结构化留痕 → 日后知识库/规则原料 |
| 工具割裂（Temu 插件 / TK 日报 / 仓桥） | 统一 **工作事件层**（人+过程），平台数据只作上下文 |

**一句话：** 市面跨境产品是「货与平台数据中台」；你们要建的是「人与过程数据中台」，平台数据是配菜。

## 2. 业界已知办法（可直接借用的范式）

| 范式 | 做什么 | 代表思路 / 来源 | 对你们的用法 |
|------|--------|-----------------|--------------|
| **异常工单 + SLA** | 告警→分派→处理→关闭；超时升级 | 跨境客服工单（Zoho/Udesk 等）、运营 SOP 手册 | 把 Temu 告警、TK 风险、仓 FAILED 都变成 Case |
| **Human-in-the-loop** | 高风险不停自动，强制人确认并记原因 | Shopify 企业自动化实践、Pipe17/Jinba 异常审核 | 发货/改预算等不可逆动作必须人点+留痕 |
| **事件日志（Process Mining 形）** | case_id + activity + actor + timestamp + outcome | Process mining / O2C 事件日志标准形 | 1.0 核心存储模型；C 阶段再挖模式 |
| **从真实工作反推 SOP** | 观察工单/聊天/处理记录 → 草稿 SOP → 人审 | Varyence SOP automation、Agent-Ops（电商 AM） | C 的路径：先有 B 的数据，才能学 |
| **Context Graph of Work** | 不只记步骤，记决策痕迹与例外逻辑 | Skan「Context Graph of Work」 | 架构预留：disposition + rationale 字段 |
| **People+Work 融合** | BI 缺「谁在干什么」层 | Visier / Prodoscore 类「工作活动智能」 | 监督看板 = 人维 × 案件维，不是再一张 GMV 图 |
| **部落知识显性化** | 把隐性经验变成可执行规则/剧本 | 制造/运营 tribal knowledge 数字化 | 一期先结构化记录，二期再规则化 |

**业界共识路径（与你们选的 A→B→C 一致）：**

```text
1.0  建 Case + 事件流 + 复盘视图（A+B）
 →   积累真实处置与结果
1.x  从事件挖掘高频模式 / 草稿 SOP（半自动，人审）
 →   C：建议处置 / 规则引擎 / 有限自动
```

**明确不要抄的：** 再做一个金蝶式「多平台订单库存全家桶」——那是市面主航道，不是你们的差异化。

## 3. 从参考材料反推：第一期该监督什么（问题 1）

> 下列为调研结论草稿，供确认；不是已定范围。

### 3.1 岗位（先小后大）

| 岗位 | 为何先做 | 参考来源 |
|------|----------|----------|
| **店铺运营（Temu）** | 已有异常发现能力，缺「谁处理、是否处理」 | Temu 项目 |
| **广告运营（TikTok）** | 已有风险标注（低 ROI / 零产出花费），缺人的处置 | TK 项目 |
| **履约/跟单（海外仓）** | 已有 FAILED/无渠道/对账差异，天然要人工介入 | 海外仓项目 |
| 采购 / Amazon | 参考图有，但几乎无既有系统 → **1.0 可后置** | 流程图（参考） |

### 3.2 可监督的具体动作（建议 1.0 清单）

| ID | 动作（员工正在做的事） | 监督信号（管理层看什么） | 数据从哪来 |
|----|------------------------|--------------------------|------------|
| W1 | 认领/响应 Temu 下架或限流告警 | 是否在 SLA 内首次响应；超时未动 | 告警→Case；操作回写 |
| W2 | 打开商品编辑/处理后提交结果 | 是否闭环；结果标签（已恢复/忽略/升级） | 处理表单 + 可选链接点击 |
| W3 | 复核 TK 低 ROI / 零产出花费项 | 当日风险是否有人看过；处理意见 | 日报风险行→Case |
| W4 | 调整广告（或记录「决定不调」及原因） | 有决策记录，而非只有花费数字 | **自创**处置记录（平台 API 可后补） |
| W5 | 为无渠道包裹做人工指派 / 处理 FAILED | 积压时长；谁在处理；是否关闭 | 仓状态机事件 + 人工动作 |
| W6 | 对账差异确认 | 差异是否当日有人确认 | 对账告警→Case |

**监督产品形态（1.0）：** 不是监视键鼠，而是 **「案件队列 + 按人/按店 SLA + 超时红灯」**——与业界工单范式一致，合规风险低于桌面监控。

## 4. 从参考材料反推：自创数据 vs 过程数据（问题 2）

### 4.1 平台提供的数据（配菜，非主菜）

在售数、流量标签、广告花费/ROI/销量、订单/运单状态……——市面已有；你们已有采集。1.0 **只接够支撑 Case 上下文的字段**。

### 4.2 「我们正在做的」过程数据（主菜 · A/B 必须落库）

统一事件形（业界事件日志最小集）：

| 字段 | 说明 |
|------|------|
| case_id | 案件 |
| actor_id | 谁 |
| activity | 认领/备注/改状态/指派渠道/关闭… |
| ts | 何时 |
| from_status / to_status | 状态变迁 |
| payload | 结构化补充（原因码、备注、关联 SKU/系列） |
| outcome | 可选：成功/无效/升级 |

### 4.3 「我们创造的」数据（主菜 · 例子）

| 类型 | 例子（来自参考能力延伸） | 为何市面没有 |
|------|--------------------------|--------------|
| 异常规则与阈值 | 「流量待关注增加即告警」、ROI 低线、白名单店 | 公司私有运营策略 |
| 处置剧本/标签 | 「下架→先查赛狐状态再编辑」「低 ROI→缩预算/关系列/观察」 | 人的决策沉淀 |
| 日报结论与亮点/风险标注 | TK 自动日报里的「亮点/风险」判断逻辑与人工修订 | 内部分析产物 |
| 渠道指派决策 | 无渠道时人选了哪条线、为何 | 履约经验 |
| 忽略/误报标记 | 「此告警为误报」 | 训练未来规则的负样本 |
| （可选后期）选品笔记、定价表、供应商议价记录 | 传统外贸核心自创资产 | 完全不在平台 API 里 |

## 5. A / B / C 分期（已按你的决定锁定）

| 阶段 | 能力 | 1.0 |
|------|------|-----|
| **A** | 存得住、查得到（事件/案件/自创对象入库可查） | **必须** |
| **B** | 按人 / 按事复盘（时间线、SLA、谁做了什么） | **必须** |
| **C** | 基于历史给建议或自动规则 | **不做实现**；表结构/事件模型/结果标签 **预留**；待 1.0 使用后积累再做 |

### C 的架构预留（现在写进 ARCH 意识，不写进 1.0 功能）

- 事件不可变追加（append-only）利于日后 process mining / 训练  
- `disposition_code` + `rationale` + `outcome_label` 强制或强鼓励填写  
- Case 类型可扩展（勿写死只服务 Temu）  
- 不做推荐 API / 自动执行器（避免范围膨胀与 G3 风险）

## 6. 推荐产品方向（给传统公司可落地的变革路径）

### 路径选择（调研结论）

| 选项 | 评价 |
|------|------|
| 买跨境 ERP/BI | 补不了差异化 1/2/3 |
| 买客服工单 SaaS | 能覆盖「人+SLA」，但不懂你们 Temu/TK/仓上下文，且难沉淀运营自创数据模型 |
| **自建「运营工作操作系统」薄平台** | **推荐：** Case + Event + 监督视图 + 接入现有三采集；飞书只做通知 |

### 建议的 1.0 切片（调研建议，待你批进 Spec）

1. **统一 Case 模型**（告警/风险/FAILED 入库即建案）  
2. **员工工作台**：我的待办 / 认领 / 填处置结果  
3. **管理层监督台**：按人、按店、超时、未闭环  
4. **案件时间线复盘（B）**  
5. 飞书：仅推送与深链回平台（非主库）  
6. 显式 **Out**：不做 C 建议引擎；不做完整 ERP；采购/Amazon 可二期  

### 变革节奏（给老板的叙事）

```text
现在：三套脚本 + 飞书喊人（有发现、无监督、无学习）
1.0 ：同一套「事」上能看见人、能复盘（组织开始有记忆）
1.x ：用记忆草稿 SOP / 规则（人审）
其后：有限自动（C）——系统核心，但不抢跑
```

## 7. 风险与合规（维 8 种子）

- 监督定位为 **业务案件 SLA**，避免做成隐蔽桌面监控（合规与士气）  
- 员工应知情：处理工作需在系统回写  
- 生产发货自动执行仍属 G3，与「记录人怎么做」分开
