# 需求收集卡 · 示例（演示用）

> 业务方视角的填法示例。真实收集请复制 `templates/INTENT-raw.md`。

### 1. 你希望最后变成什么样？

客服打开工单后，能一键生成一段「用户听得懂的进度说明」，复制发给用户。

### 2. 主要是谁在用？在什么情况下用？

一线客服；用户追问「我的单到哪了」的时候。

### 3. 现在是怎么做的？哪里不顺？

翻好几条系统日志自己拼话；大约四五分钟，还容易把内部状态说错。

### 4. 怎样算「做成了」？

测试环境里：打开工单到复制出摘要不超过半分钟；摘要里有当前状态和最近一次变更时间；失败时有明确原因，不能假成功。

### 5. 这次明确先不做哪些？

1. 不做自动发消息给用户  
2. 先不做手机 App  
3. 不改工单本身的状态流转规则  

### 6. 什么时候希望能用上？

这个迭代内能给组长演示即可，没有死线。

### 7. 有没有绝对不能碰的规矩？

不能直连生产库；摘要默认不要进长期日志。

### 8. 改现有还是从零？

- [x] 改我们已经在用的系统 / 页面 / 功能  
- 工单详情页（Web）
