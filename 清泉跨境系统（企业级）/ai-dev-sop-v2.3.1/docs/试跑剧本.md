# 试跑剧本 — 端到端 Pilot

> 目的：在真实写业务代码前，用**示例材料**走通 SOP 全链路，暴露安装与协作摩擦。  
> 预计耗时：**30～45 分钟**（到 Gate A 即可；完整到 PR 约 60～90 分钟）。  
> 记录结果：复制章节到 [`试跑记录.md`](./试跑记录.md)。

---

## 0. 前置

- [ ] 已执行：`./install.sh`（用户级多客户端链；团队仓另可 `--into`）
- [ ] 工具中能搜到 / 调用 **`/ai-dev-sop`**
- [ ] 参与角色（可同一人分饰）：业务口述、产品整理、执行者批门禁

---

## 1. 安装校验（5 min）

```bash
# 在 SOP 仓库根
./install.sh --check
./skills/ai-dev-sop/scripts/check-dor.sh docs/specs/SPEC-smoke.md docs/specs/ACCEPTANCE-smoke.md
```

| 检查 | 期望 |
|------|------|
| install --check | RESULT: OK |
| check-dor smoke | RESULT: PASS |
| Agent 客户端 Skill 列表 | 可见 `ai-dev-sop` |

失败 → 先修安装，不进入试跑。

---

## 2. 甲方收集（5 min）

1. 打开示例：[`specs/INTENT-raw-example.md`](./specs/INTENT-raw-example.md)  
   或复制 `templates/INTENT-raw.md` 自填一版极简需求。  
2. 确认：无 `feature/greenfield` 等研发黑话，业务能读懂。

| 检查 | 期望 |
|------|------|
| raw 有「做成什么样 / 谁用 / 痛点 / 算做成」 | 是 |
| 业务方不需要懂 mode | 是 |

---

## 3. 产品整理 INTENT（10 min）

1. 对照 raw，打开示例整理稿：[`specs/INTENT-example.md`](./specs/INTENT-example.md)  
2. 或从 `templates/INTENT.md` 新建 `docs/specs/INTENT-pilot.md`  
3. 确认 0.7 为白话+枚举，如：`改已有系统（feature）`  
4. 0.11 指向 raw 路径  

| 检查 | 期望 |
|------|------|
| §0 齐全 | 是 |
| 成功标准可观测 | 是 |
| 至少 1 条「不做」 | 是 |

---

## 4. 启动 Agent · PHASE 0–1（10～15 min）

对话粘贴：

```text
/ai-dev-sop

按 AI 开发 SOP 从 L1 开始。禁止直接写业务代码。
INTENT 见下方（或路径 docs/specs/INTENT-example.md）：

（粘贴 INTENT-example 全文）
```

观察 Agent 是否：

- [ ] 识别为结构化 INTENT（非 raw）
- [ ] 声明 mode / 开工类型
- [ ] Read `workflow` / `l1-scan` / `skill-pack/01`
- [ ] 提问或标 `[ASSUMES:]`，而不是直接写码
- [ ] 起草 SPEC + ACCEPTANCE 工作副本
- [ ] 运行或提示运行 `check-dor.sh`
- [ ] 输出：`SPEC READY — waiting for approval`

| 违规 | 处理 |
|------|------|
| 未批 Spec 就改业务代码 | **试跑失败**；叫停并记录 |
| 未出哨兵句 | 失败；要求按 SKILL 重来 |

人回复：`批准`（或按草稿改一版再批）。

---

## 5. PHASE 2 · Gate M（5～8 min）

期望：

- [ ] 加载 `skill-pack/02-mvp-cut`
- [ ] 写出 Ship-now / Defer / Success（可填 SPEC §2.4）
- [ ] 输出：`MVP READY — waiting for approval`
- [ ] 批准前无 Plan、无业务代码

人：`批准`。

| 违规 | 处理 |
|------|------|
| Spec 批后直接 `PLAN READY` | **试跑失败**；补 Gate M |

---

## 6. PHASE 3 · Gate D 架构（5～10 min）

期望：

- [ ] 加载 `skill-pack/03-arch-design`
- [ ] 写出 `ARCHITECTURE-*.md`（或 N/A+理由）
- [ ] 输出：`ARCH READY — waiting for approval`
- [ ] 制品进仓，不只在对话里

人：`批准`。

---

## 7. PHASE 4 · Gate A（10 min）

期望：

- [ ] 加载 `skill-pack/04`
- [ ] Plan 引用 MVP+ARCH；文件列表 ⊆ Ship-now 且落在 ARCH 内
- [ ] 输出：`PLAN READY — waiting for approval`
- [ ] 批准前无业务代码写入

人：`批准`（试跑可在此结束，标「部分通过」）。

---

## 8. （可选）Findings → 实现 → Diff

| 步 | 哨兵句 | 人 |
|----|--------|-----|
| Gate B | `FINDINGS READY — waiting for approval` | 批准 / N/A |
| 实现 | 无 | 看是否贴 Plan/MVP |
| Gate C | `DIFF READY — waiting for approval` | 批准后再 commit |

试跑若在假想仓库无真实代码：Gate B 可练 N/A 话术；实现可跳过，**Gate C 流程仍口述一遍**。
