# AI 开发 SOP — 使用说明（v2.3.1）

面向：**管理者 / 产品 / 开发员工 / Agent 执行者**。  
一句话：用**门禁 + 进仓交付物**管 AI 辅助开发，避免「聊完就开写」。

本包按通用 Skill 约定编写，**不绑定单一厂商产品**；安装脚本可同时写入多套客户端目录（见 §2.2）。

---

## 1. 这是什么

一套可启动的 Skill（`/ai-dev-sop`）+ 模板 + 分阶段子技能包。

| 角色 | 你要做什么 |
|------|------------|
| 甲方/业务 | 填白话需求卡 |
| 产品/负责人 | 整理 INTENT；批 Spec、MVP |
| 技术负责人 | 批架构、Plan、Diff |
| 开发员工 | 按节点交文件；在哨兵处等批准 |
| Agent | 执行 SOP；未批不得写业务代码 |

**核心原则**：每个硬节点 = **哨兵句 + 人批准 + 进仓文件**。聊天里说「行」不算完成。

## 2. 安装

### 2.1 推荐（个人，用户级）

解压本包后，在包根目录执行：

```bash
chmod +x install.sh
./install.sh --no-project
```

校验：

```bash
./install.sh --check
```

看到 `RESULT: OK` 即可。之后在任意业务工作区对 Agent 输入 **`/ai-dev-sop`**。

### 2.2 客户端适配路径（安装脚本写入）

默认 `--tool all` 会同时链到下列目录（有则生效，互不影响）：

| 适配 | 用户级 | 项目级 |
|------|--------|--------|
| A | `~/.cursor/skills/ai-dev-sop` | `.cursor/skills/ai-dev-sop` |
| B | `~/.claude/skills/ai-dev-sop` | `.claude/skills/ai-dev-sop` |
| C | `~/.grok/skills/ai-dev-sop` | `.grok/skills/ai-dev-sop` |
| 通用 | `~/.agents/skills/ai-dev-sop` | `.agents/skills/ai-dev-sop` |

只装其中一种：

```bash
./install.sh --tool cursor    # 仅 A
./install.sh --tool claude    # 仅 B
./install.sh --tool grok      # 仅 C
./install.sh --tool agents    # 仅通用
```

### 2.3 同步进业务仓库（团队）

```bash
./install.sh --into /path/to/your-product-repo
```

会同步：`skills/`、`skill-pack/`、`templates/`、关键 `docs/`、以及 `AGENTS.md` 路由块，并写项目级 Skill 链。

### 2.4 其他

```bash
./install.sh --no-global --tool all   # 只写项目级
./install.sh --copy                   # 复制代替 symlink
```

## 3. 日常怎么用（5 步）

```text
1. 甲方填 templates/INTENT-raw.md（白话）
2. 产品整理成 templates/INTENT.md（至少填 §0）
3. 在 Agent 对话中输入：/ai-dev-sop
   然后粘贴整理后的 INTENT（或给出 docs/specs/INTENT-xxx.md 路径）
4. 按提示回答澄清问题；在每个哨兵句后审阅**进仓文件**再回复「批准」
5. Diff 批准后再 commit / 开 PR（禁止 Agent 自动合 main）
```

### 3.1 启动话术示例

```text
/ai-dev-sop

按 AI 开发 SOP 从 L1 开始。禁止直接写业务代码。
INTENT 见下方：

（粘贴 INTENT.md 全文）
```

### 3.2 你只需要记住的回复

| 情况 | 回复 |
|------|------|
| 同意继续 | `批准` |
| 缩小范围 | `批准，但 Ship-now 不要含 X` |
| 不对 | `不批准：应先改 Y` |
| 超权限 | `升级审批：涉及资金/生产…` |

## 4. 流程与哨兵句

```text
PHASE 0  mode
PHASE 1  Spec          → SPEC READY — waiting for approval
PHASE 2  MVP           → MVP READY — waiting for approval
PHASE 3  架构          → ARCH READY — waiting for approval
PHASE 4  Plan          → PLAN READY — waiting for approval
PHASE 5  Findings      → FINDINGS READY — waiting for approval（可 N/A）
PHASE 6  实现
PHASE 7  Diff / PR     → DIFF READY — waiting for approval
PHASE 8  （可选）回写规则
```

| 制品 | 看见什么 |
|------|----------|
| **MVP** | 本迭代交付面（用户能感知什么） |
| **ARCHITECTURE** | 内部结构（模块、数据流、边界） |
| **PLAN** | 改哪些文件、怎么验证 |

详表：[docs/节点交付物.md](./docs/节点交付物.md)

## 5. 交付物放哪

建议统一写在**当前业务仓**：

```text
docs/specs/INTENT-<slug>.md
docs/specs/SPEC-<slug>.md
docs/specs/ACCEPTANCE-<slug>.md
docs/specs/MVP-<slug>.md            # 或写在 SPEC §2.4
docs/specs/ARCHITECTURE-<slug>.md
docs/specs/PLAN-<slug>.md
```

模板在包内 `templates/`。复制后改名填空即可。

## 6. 管理者怎么检查员工

对照 [节点交付物.md](./docs/节点交付物.md)：

1. **有没有文件路径？** 只有聊天记录 → 打回  
2. MVP ⊆ Spec？架构撑得住 Ship-now？Plan ⊆ MVP 且落在 ARCH 内？  
3. Diff 有没有超出 Plan/ARCH？  
4. skip / N/A 有没有写理由？  

热修：可跳 MVP/架构/Plan（须书面理由），**不可跳 Diff**。

---

## 7. 小改 / 热修 / 新项目

| 场景 | 做法 |
|------|------|
| 小改、无模块边界变化 | 架构可 **N/A**（文件里写理由，仍要 `ARCH READY` + 批准） |
| 单文件热修且拒绝完整 SOP | 可 skip M/D/A/B；必须 `DIFF READY` |
| greenfield / 新模块 | 架构**必须**有图（mermaid 即可） |
| Spec 范围变更 | 打回 PHASE 1 |
| 只改本迭代切片 | 打回 PHASE 2 改 MVP |

## 8. 禁止事项（G3）

Agent **不得擅自**：生产部署、删数、提交密钥、改支付/结算、配外部生产凭据、改法定/合规字段、用生产 PII 调试。  
触及则升级授权审批人。

## 11. 常见问题

**Q：Skill 列表里看不到 `/ai-dev-sop`？**  
A：确认已执行 `./install.sh`；重启客户端会话；检查 §2.2 对应目录下是否有 `ai-dev-sop/SKILL.md`。

**Q：Agent 直接写代码？**  
A：叫停；要求从当前未过门禁重来；在 PR/记录里记事故。可后续启用 `docs/hooks-草案.md`。

**Q：业务仓里找不到 skill-pack？**  
A：用户级安装时按 SOP_ROOT 读本包路径；或对该业务仓执行 `./install.sh --into <仓>`。

**Q：DoR 脚本怎么跑？**  

```bash
./skills/ai-dev-sop/scripts/check-dor.sh docs/specs/SPEC-xxx.md docs/specs/ACCEPTANCE-xxx.md
```

脚本 PASS 仍须人批准 Spec，再批 MVP/架构。
