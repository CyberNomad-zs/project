# 清泉中台 · 产品蓝图

> 版本：v1.0  
> 日期：2026-07-28  
> 来源：`中台.xmind`  
> 对齐文档：[架构方案.md](./架构方案.md) · [会议纪要-技术会.md](./会议纪要-技术会.md) · [Phase0-实施计划.md](./Phase0-实施计划.md)

---

## 1. 文档目的

将 `中台.xmind` 中的**组织/经营视角**固化为可执行的产品蓝图，并与既有「清泉跨境」技术基座（PostgreSQL SoT、任务引擎、Ingest、飞书同步）对齐。

**一句话：**  
中台 = **老板驾驶舱** + **部门/平台业务空间**；技术底座复用 Phase0，业务按部门分期交付。

---

## 2. 导图原文结构（整理）

```
中台
└── 老板驾驶舱
    ├── 采购
    │   ├── 仪表盘
    │   └── 数据同步 → 使用改进
    ├── AMZ
    │   ├── 补货 → 助理（唐丹/其他运营）→ 终审（李瑾）
    │   ├── 数据分析（赛狐接口）
    │   │   ├── 按链接 日/周/月 环比数据异常
    │   │   │   └── 以人为维度的任务表 → 推送第一负责人 + 权限
    │   │   │       └── 第一负责人填写运营动作 → 跟踪直到完成
    │   │   └── 巡店 → 检查店铺异常 → 插件 · 飞书 · 任务
    │   └── 仪表盘（张帅）
    ├── TK          （占位，待展开）
    ├── TEMU        （占位，待展开）
    ├── 财务
    │   └── 数据计算 → 中台
    │       ├── 平台利润表 → 赛狐补差 → AI
    │       ├── 公司现金流表 → 飞书出纳银行余额 / 采购货值 / 采购未付
    │       ├── 边际利润表 → 当月平台利润 − 出纳当月实际支出 → 每月净利润
    │       ├── 打款分布 → 资金链测算
    │       └── 报税 → 数据处理后生成报税报表
    └── 美工
        ├── 所有部门汇总推送 → 任务完成推送相应部门
        └── 任务表 + 仪表盘
```

## 3. 产品定位

| 维度 | 说明 |
|------|------|
| 用户 | 老板、各平台运营、采购、财务、美工、助理 |
| 入口 | Web 管理端（部门/平台空间）+ 飞书（任务/报表/通知）+ 企业智能体（主通知通道） |
| 原则 | **流程相同上收全局**；**流程不同沉到部门/平台**；人、权、审独立建模 |
| SoT | PostgreSQL；飞书为协作与同步出口，不做唯一主库 |

与 [架构方案](./架构方案.md) 的关系：

| 架构方案侧重 | 中台蓝图侧重 |
|--------------|--------------|
| 采集、Ingest、任务状态机、分期技术交付 | 老板驾驶舱、部门空间、审批链、财务五表、人维任务 |
| 平台 = Amazon / TikTok / Temu 运营能力 | 平台 + **采购 / 财务 / 美工** 组织能力 |

两者叠加：技术分期不推翻，产品导航与优先级按本蓝图校正。

- 总览：老板驾驶舱（默认首页）+ 工作台

- 系统工具底部折叠：异常任务中心、店铺主数据、插件中心、AI报表、**飞书同步**  
- 财务为单菜单 + **页内 Tab**（五表）；AMZ「总览」合并原平台总览与仪表盘

## 5. 业务域说明

### 5.1 老板驾驶舱

**目标：** 一张视图看经营健康，不下钻细节。

建议指标分组（首期可 mock / 汇总已有任务与店铺）：

| 分组 | 示例指标 |
|------|----------|
| 运营风险 | 未闭环异常数（分平台）、超时任务、巡店失败店数 |
| 履约 | 发货异常（Temu/海外仓，若已上报） |
| 采购 | 断货/滞销任务、补货待审单量 |
| 财务摘要 | 月净利润趋势、现金余额、采购未付（有数据后再上） |

**权限：** 老板 + 指定高管；部门负责人默认可看本域。

---

### 5.2 采购

| 能力 | 导图表述 | 与技术会/架构对齐 |
|------|----------|-------------------|
| 仪表盘 | 采购仪表盘 | 销售天数、滞销断货、供应商（脱敏） |
| 数据同步 | 同步 + **使用改进** | 飞书/中心表同步；收集业务改进意见闭环 |
| 补货终审 | 见 AMZ 补货（终审李瑾） | 采购部对接人李瑾（会议纪要） |

**任务类型（建议）：** `purchase_replenish` / `stockout` / `slow_moving`  
**脱敏：** 供应商名称仅 `procurement_full` 角色可见，其余见编号（沿用架构方案）。

---

### 5.3 Amazon（样板域，优先做实）

导图将 AMZ 写得最细，作为 **平台域标准模板**。

#### 5.3.1 补货

| 项 | 内容 |
|----|------|
| 流程 | 助理发起（唐丹 / 其他运营）→ **终审李瑾** → 通过/驳回 |
| 系统能力 | 审批流状态机：`draft → pending_review → approved / rejected`；驳回可重提 |
| 通知 | 待审 → 李瑾；结果 → 发起人 |
| 数据 | 链接/ASIN、建议量、库存、销售天数、备注 |

#### 5.3.2 数据分析 · 环比异常（核心闭环）

```
赛狐接口
  → 按链接聚合 日/周/月 指标
  → 环比异常判定（规则可配置，首期阈值可运营配置）
  → 生成「以人为维度」的任务
  → 推送第一负责人 + 店铺/任务权限
  → 负责人填写运营动作
  → 跟踪直至闭环
  → 闭环后再出现同类异常 → 新建任务（不复活旧单）
```

与现有任务引擎对齐：

| 现有 | 中台补充 |
|------|----------|
| 去重键 `platform + biz_id + anomaly_type` | 保留；列表/推送增加 **owner 人维视图** |
| 状态 open / in_progress / resolved | 不变；进度备注 = 运营动作 |
| 飞书同步任务表 | 同步 + 智能体/机器人推送第一负责人 |

**异常类型示例（AMZ）：**  
`link_wow_drop` / `link_mom_drop` / `sales_anomaly` / `account_health` 等（字段字典后续增补）。

#### 5.3.3 巡店

| 项 | 内容 |
|----|------|
| 动作 | 检查店铺异常（前台/绩效，对齐会议 12 项 + 赛狐绩效） |
| 链路 | **插件 → 飞书 → 任务**（异常才建单） |
| 技术 | `collectors/amazon-extension` + Ingest + task_engine |

#### 5.3.4 仪表盘

| 项 | 内容 |
|----|------|
| 负责人 | 张帅 |
| 内容 | 本平台 KPI、未闭环任务、补货待审、巡店覆盖率 |

### 5.4 TikTok / Temu

| 平台 | 导图状态 | 建议骨架（抄 AMZ） | 已有资产 |
|------|----------|-------------------|----------|
| TK | 占位 | 总览 · 广告投流 · 运营异常 · 仪表盘 · 人维任务 | TK 广告项目 + dual 上云方案 |
| TEMU | 占位 | 总览 · 健康监测 · 自动化发货（桥独立）· 异常任务 | Temu 插件/monitor + 海外仓 |

发货：Phase 0–3 **不并入发货主链路**（架构已定），中台仅展示/上报状态与异常。

---

### 5.5 财务（独立子域）

在中台内完成**数据计算与报表**，非简单同步。

| 报表 | 数据来源（导图） | 产出 |
|------|------------------|------|
| 平台利润表 | 赛狐 + 补差逻辑 | 分平台利润；补差可 AI 辅助 |
| 公司现金流表 | 飞书出纳银行余额 + 采购货值 + 采购未付 | 现金水位视图 |
| 边际利润表 | 当月平台利润 − 出纳当月实际支出 | **每月净利润** |
| 打款分布 | 付款流水 | 资金链测算 |
| 报税 | 处理后结构化数据 | 报税报表 |

**依赖：**

1. 赛狐财务/订单类只读接口（或导出落库）  
2. 飞书多维表：出纳银行余额、实际支出  
3. 采购货值 / 未付与采购域打通  
4. 计算任务可调度（日/月）+ 审计日志  

**权限：** 财务角色 + 老板驾驶舱摘要；运营默认不可见明细。

---

### 5.6 美工

| 能力 | 说明 |
|------|------|
| 任务表 + 仪表盘 | 设计需求任务、进度、SLA |
| 跨部门汇总推送 | 各部门提需汇总；**任务完成再推送相应需求部门** |
| 通知 | 飞书/智能体；与统一任务引擎可共用状态机，类型 `design_*` |

## 6. 横切能力（必须统一）

### 6.1 任务模型扩展

在现有 `task` 表能力上扩展（实施时 migration，不必 Phase0 改完）：

| 字段/概念 | 用途 |
|-----------|------|
| `owner_user_id` | 第一负责人（已有） |
| `domain` | 业务域：ops / purchase / finance / design |
| `platform` | amazon / tiktok / temu / none |
| 人维视图 API | `GET /tasks?owner_user_id=` + 按人聚合看板 |
| 审批单 `approval` | 补货等：多级审批，与 task 可关联可独立 |

**去重规则（运营异常，不变）：**  
`platform + biz_id + anomaly_type` 未闭环只更新；闭环后再建。

**人维推送：** 生成任务后按 `owner` 聚合通知，避免一人一天 N 条碎片（架构「收敛通知」）。

### 6.2 权限与组织

| 角色（建议） | 范围 |
|--------------|------|
| boss | 驾驶舱 + 跨域只读 |
| amz_ops / tk_ops / temu_ops | 本平台任务与仪表盘 |
| purchase / purchase_approver | 采购 + 补货终审（李瑾） |
| finance | 财务五表 |
| design | 美工任务 |
| admin | 全量 + 店铺/插件/同步配置 |

店铺数据权限、采集 API Key 范围沿用架构方案。

### 6.3 通知通道

```
领域事件 → Router
  ├─ 企业智能体（主通道，会议红标）
  ├─ 飞书群/个人
  └─ 邮件（采购试行）
```

场景：新任务、待审批、驳回、闭环、每日必提醒、美工完成回推。

### 6.4 数据与集成

| 系统 | 用途 |
|------|------|
| 赛狐 OpenAPI | AMZ/采购/财务补差、销售天数、链接指标 |
| 浏览器插件 / 紫鸟 | 巡店、TK 广告、Temu 监测 |
| 飞书 Bitable | 任务同步、出纳余额、协作表 |
| 海外仓 bridge | 发货独立；库存/异常事件可上报 |

## 7. 与分期路线对齐

在 [架构方案 §5](./架构方案.md) 基础上，按中台蓝图**校正优先级**（不推翻周期量级）：

| 阶段 | 原架构重点 | 中台蓝图落地重点 |
|------|------------|------------------|
| **Phase 0** | 基座、Ingest、任务、飞书 MVP、登录/店铺、Web 壳 | 保持；Web 导航预留部门结构；任务支持人维筛选演示 |
| **Phase 1** | TK 上云、Temu 上云、赛狐只读 SDK | **+ AMZ 环比异常 → 人维任务 → 推送**（样板闭环）；采购仪表盘雏形 |
| **Phase 2** | 亚马逊销售/账号巡检 12 项、FBA/FBM | **+ 巡店插件链路**；**补货审批流**；**Amazon 自动化发货（FBM 接 WMS）**；AMZ 仪表盘（张帅） |
| **Phase 3** | TK 运营扩展、Temu 物流链接、采购供应商/滞销/邮件 | **+ 采购数据同步与使用改进**；美工任务推送；TK/TEMU 按 AMZ 骨架补齐 |
| **Phase 4** | 看板、智能体查数催办、规则 UI、发货评估 | **+ 老板驾驶舱定稿**；**财务五表与资金链/报税**；AI 利润补差 |

## 10. 开放问题（需业务确认）
